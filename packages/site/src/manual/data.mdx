Programs exchange data with other programs as text, most often as JSON or CSV. The global functions [`fromjson`](/manual/api#fromjson) and [`tojson`](/manual/api#tojson) convert between JSON text and tables, as [`fromcsv`](/manual/api#fromcsv) and [`tocsv`](/manual/api#tocsv) do for CSV. The [`table`](/manual/api#table-library) library has functions that summarize, transform, group, and sort the tables. The [`string`](/manual/api#string-library) library has functions that split, join, and trim text.

## JSON

_JSON_ is a text format for structured data. It holds numbers, strings, booleans, lists, and records with named fields, where lists and records can nest to any depth. Web APIs and configuration files often use JSON. The function `fromjson` converts JSON text to Lus values, which `tojson` converts back to JSON text. Both follow the JSON standard, RFC 8259.

The following program reads a configuration, changes the port of the server, then writes the address of the server as JSON.

```lus
global fromjson, print, tojson

local config = fromjson([[
{
    "server": { "host": "localhost", "port": 8080 },
    "tags": ["web", "api"],
    "debug": false
}
]])
print(config.server.port, config.tags[1], config.debug)  --> 8080  web  false

config.server.port = 9090
print(tojson({ config.server.host, config.server.port }))  --> ["localhost",9090]
```

### Parsing

`fromjson(s, options)` parses the string `s`, which must hold exactly one valid JSON value. JSON values become Lus values as follows:

- `null` becomes `nil`.
- `true` and `false` become booleans.
- A number without a decimal point or an exponent becomes an integer. A number with either one becomes a float.
- A string becomes a string.
- An array becomes a table with integer keys from 1.
- An object becomes a table with string keys. If an object repeats a key, the table holds the last value.

```lus
global fromjson, math, print

print(math.type(fromjson("42")), math.type(fromjson("1e2")))  --> integer  float
print(fromjson("null"), fromjson("true"), fromjson('"hi"'))  --> nil  true  hi
print(fromjson('{"a": 1, "a": 2}').a)  --> 2
```

Because a table cannot hold `nil`, a null field of an object is absent from the resulting table. A null element of an array leaves a gap. JSON that contains null values therefore changes when a program parses it and writes it back.

```lus
global fromjson, print, tojson

local row = fromjson("[1, null, 3]")
print(row[1], row[2], row[3])  --> 1  nil  3
print(tojson(fromjson('{"a": null}')))  --> []
```

Prices and long identifiers must keep every digit when a program reads them, but a float stores most decimal fractions approximately and an integer holds at most 64 bits. The `exact` field of the optional `options` table makes `fromjson` keep every digit. When `exact` is `true`, an integer too large for 64 bits becomes a bigint, while a number with a fraction or an exponent becomes a decimal, which keeps its digits as written. `tojson` writes both with the same digits. [Values and types](/manual/guide#values-and-types) in the guide describes bigints and decimals.

```lus
global fromjson, math, print, tojson

local price = fromjson('{"price": 19.90}', { exact = true }).price
print(math.type(price), price, tojson(price))  --> decimal  19.90  19.90

local id = fromjson("123456789012345678901234567890", { exact = true })
print(math.type(id), tojson(id))  --> bigint  123456789012345678901234567890
```

Without `exact`, a number outside the range of a 64-bit integer or a float raises an error. Invalid syntax, text after the end of the value, and arrays and objects nested deeper than 1,000 levels also raise errors. The error message gives the position of the problem in bytes from the start of the text, counting the first byte as position 1.

```lus
global fromjson, print

print(catch fromjson('{"invalid}'))  --> false  ...: JSON parse error at position 11: unterminated string
print(catch fromjson("[1] x"))  --> false  ...: JSON parse error at position 5: unexpected trailing characters
print(catch fromjson("99999999999999999999"))  --> false  ...: JSON parse error at position 1: number out of range
```

### Serializing

`tojson(value, filter)` returns the JSON text of `value` as a string, without spaces or line breaks.

A Lus table can be a list or a record, while JSON has a separate form for each: an array and an object. `tojson` chooses the form from the keys of the table. The empty table and a table whose keys are all positive integers become JSON arrays. The array runs from 1 to the largest key, with `null` in each missing position, so a list with a `nil` in the middle keeps its length. Every other table becomes a JSON object that contains the string keys of the table and omits keys of every other type.

A `nil` at the end of a list has no key, so it leaves no `null` behind. When the largest key is above 10 and half or fewer of the positions up to it hold a value, the table becomes a JSON object instead, with the integer keys written as decimal strings in ascending order. A table such as `{[1000000] = true}` therefore becomes `{"1000000":true}` and not a million `null` values. The shape of the output then depends on the data, so a program that reads it back must accept both forms, or keep its lists dense.

```lus
global print, tojson

print(tojson({ 10, 20, 30 }))  --> [10,20,30]
print(tojson({}))  --> []
print(tojson({ 1, 2, name = "pair" }))  --> {"name":"pair"}
print(tojson({ [1] = "a", [3] = "c" }))  --> ["a",null,"c"]
```

The order of the members of an object is unspecified, so a program must not compare the output of `tojson` with a fixed string when the value contains a record with several fields.

Numbers serialize as follows:

- An integer, a bigint, or a decimal is written with its exact digits.
- A float with a whole value is written without a decimal point, so it parses back as an integer.
- Any other float is written with the fewest significant digits, from 14 up to 17, that parse back to the same float, so `0.1` stays `0.1`.
- An infinity or NaN becomes `null`.

```lus
global math, print, tojson

print(tojson(3.0), tojson(0.1))  --> 3  0.1
print(tojson(math.huge), tojson(0 / 0))  --> null  null
```

Functions, coroutines, userdata, vectors, and enum values have no JSON form. Each becomes `null` when it is the whole value or an element of an array, but an object field that holds one is left out.

```lus
global print, tojson

local status = enum ready, done end
print(tojson(status.ready))  --> null
print(tojson({ status.ready }))  --> [null]
print(tojson({ status = status.ready }))  --> {}
```

A table that is referenced from several places is written in full at each place. A table that contains itself, directly or indirectly, raises the error `circular reference detected in table`.

```lus
global print, tojson

local child = { value = 1 }
print(tojson({ child, child }))  --> [{"value":1},{"value":1}]

local cycle = {}
cycle.self = cycle
print(catch tojson(cycle))  --> false  ...: circular reference detected in table
```

`tojson` writes tables nested up to 199 levels deep and raises the error `C stack overflow` for a deeper table.

### Filters

A program often needs to omit or change some values in its JSON output, such as a password field or an internal identifier. The optional `filter` argument of `tojson` is a function that changes values in the output and leaves the data unchanged. `tojson` first calls the filter with the key `nil` and the whole value, then for each integer key of an array and each string key of an object, with the key and the value at that key. `tojson` writes the value that the filter returns. When that value is a table, `tojson` filters its contents in the same way.

A filter that returns `nil` for a field of an object removes the field. A filter that returns `nil` for an element of an array or for the whole value writes `null`. An error raised in the filter propagates from `tojson`.

```lus
global print, tojson

local user = { name = "Alice", password = "secret" }

print(tojson(user, function(key, value)
    if key == "password" then
        return nil
    end

    return value
end))  --> {"name":"Alice"}

print(tojson({ 1, 2, 3 }, function(key, value)
    if key == 2 then
        return nil
    end

    return value
end))  --> [1,null,3]
```

### The `__json` metamethod

An object of a class usually holds fields that do not belong in its JSON form, so a class defines the JSON form of its objects once with the `__json` metamethod. When a table has a [metatable](/manual/guide#metatables-and-objects) with a `__json` field, `tojson` calls `__json` with the table and writes the value that the call returns. `tojson` serializes the returned value by the same rules, so that value may have a `__json` metamethod of its own. If `__json` returns `nil`, the table is written as `null`. An error raised in the metamethod propagates from `tojson`.

```lus
global fromjson, print, setmetatable, tojson

local Point = {}
Point.__index = Point

Point.__json = function(self)
    return { x = self.x, y = self.y }
end

local point = setmetatable({ x = 10, y = 20, internal = "data" }, Point)
local decoded = fromjson(tojson(point))
print(decoded.x, decoded.y, decoded.internal)  --> 10  20  nil
```

A field that holds `nil` is absent from the output. To write `null` for a field, give the field a table with a `__json` metamethod that returns `nil`.

```lus
global print, setmetatable, tojson

local null = setmetatable({}, {
    __json = function()
        return nil
    end,
})

print(tojson({ email = null }))  --> {"email":null}
```

## CSV

_CSV_ is a text format for a table of values, in which each line is a row and commas separate the fields of a row. Spreadsheets and databases export and import CSV. `fromcsv` parses CSV text into a table of rows, which `tocsv` writes back as CSV text. Both follow the CSV standard, RFC 4180.

The following program computes the total of a list of orders from CSV text whose first line names the columns. The prices are money, so the program converts them to [decimals](/manual/practices#numbers), which keep their cents exactly.

```lus
global decimal, fromcsv, ipairs, print, tonumber

local orders = fromcsv("item,quantity,price\npen,3,1.50\nnotebook,2,4.25\n", true)
local total = 0d

for _, order in ipairs(orders) do
    total = total + tonumber(order.quantity) * decimal(order.price)
end

print(#orders, orders[1].item, total)  --> 2  pen  13.00
```

### Parsing CSV

`fromcsv(s, headers, delimiter)` returns an array with one entry per row, where each row is an array of strings. CSV has no types, so every field is a string. A program converts the fields that hold numbers with `tonumber`, or with `decimal` for money.

```lus
global fromcsv, print

local data = fromcsv("name,age,city\nAlice,30,Paris\nBob,25,London")
print(#data, data[1][1], data[2][1], data[2][2])  --> 3  name  Alice  30
```

Most CSV files name their columns in the first row. When `headers` is `true`, `fromcsv` reads the column names from the first row and turns each later row into a table with one field per column name. A program can then read `row.age`, which keeps working when the columns change order, unlike `row[2]`. A row with fewer fields than the header has no field for the missing columns. A field beyond the last column name is dropped.

```lus
global fromcsv, print

local people = fromcsv("name,age,city\nAlice,30,Paris\nBob,25,London", true)
print(#people, people[1].name, people[1].age, people[2].city)  --> 2  Alice  30  London
```

A CSV field that contains the delimiter, a line break, or a double quote is enclosed in double quotes, with each double quote inside it written twice. `fromcsv` reads these forms and returns the field without the enclosing quotes. A row ends with a line feed, or with a carriage return followed by a line feed. A line break at the end of the text adds no row, but an empty line inside the text is a row with one empty field.

```lus
global fromcsv, print

local data = fromcsv('"hello, world","she said ""hi"""\r\n"two\nlines",x')
print(data[1][1], data[1][2])  --> hello, world  she said "hi"
print(#data, data[2][2])  --> 2  x
```

The optional `delimiter` is a single character, `","` by default, for files that separate fields with a tab or a semicolon. A longer delimiter raises an error.

```lus
global fromcsv, print

local data = fromcsv("name\tage\nAlice\t30", false, "\t")
print(data[2][1], data[2][2])  --> Alice  30
```

A quoted field without a closing quote raises an error, as does a closing quote followed by anything other than the delimiter, a line break, or the end of the text. The message gives the byte position of the problem.

```lus
global fromcsv, print

print(catch fromcsv('"unterminated'))  --> false  ...: CSV parse error at position 14: unterminated quoted field
print(catch fromcsv('"a"b,c'))  --> false  ...: CSV parse error at position 4: unexpected character after quoted field
```

### Writing CSV

`tocsv(rows, delimiter)` returns a string with one line per row, where every line, including the last, ends with a line feed. Each row must be an array of fields, with the header line as a row like the others. A row that is not a table raises the error `row N is not a table`. `tocsv` reads only the fields at indices 1 to the length of a row, so a row that has only named fields produces an empty line.

```lus
global print, tocsv

local csv = tocsv({
    { "name", "age" },
    { "Alice", 30 },
})
print(csv == "name,age\nAlice,30\n")  --> true
```

`tocsv` converts each value that is not a string with `tostring`. The number of fields in a row is the length that the `#` operator returns, where a `nil` inside that length becomes an empty field. A `nil` can also make `#` return a shorter length, so a program should write an empty field as `""`. A field that contains the delimiter, a line break, or a double quote is enclosed in double quotes, with each double quote inside it written twice.

```lus
global print, tocsv

print(tocsv({ { 1, true, 3.14 } }) == "1,true,3.14\n")  --> true
print(tocsv({ { "a", "", "c" } }) == "a,,c\n")  --> true
print(tocsv({ { "hello, world", 'say "hi"' } }) == '"hello, world","say ""hi"""\n')  --> true
```

The optional `delimiter` is a single character and defaults to `","`.

```lus
global print, tocsv

print(tocsv({ { "a", "b" }, { "c", "d" } }, "\t") == "a\tb\nc\td\n")  --> true
```

## Table functions

The `table` library has functions that summarize, transform, group, and sort a list of values or records. Each function reads its array argument from index 1 to the length that `#` returns.

### Statistics

The statistics functions of the `table` library summarize the numbers in an array. A string that holds a number is treated as that number, so the functions accept the fields of a CSV row, while every other value is skipped. The following functions summarize an array:

- [`table.sum`](/manual/api#table.sum) returns the sum. The sum of integers is an integer, as with `+`. The sum of an array with no numbers is `0`.
- [`table.mean`](/manual/api#table.mean) returns the average as a float, which is the sum divided by the count.
- [`table.median`](/manual/api#table.median) returns the middle value of the sorted numbers, or the average of the two middle values as a float when their count is even. One unusually large or small value changes the median far less than the mean. The function leaves the array unchanged.
- [`table.stdev(array, sample)`](/manual/api#table.stdev) returns the standard deviation as a float, which measures how far the values spread around their mean. It divides by the count `n`, which is correct when the array holds every value of interest. When `sample` is `true`, it divides by `n - 1`, which is correct when the array is a sample of a larger set.

`table.mean`, `table.median`, and `table.stdev` return NaN when the array has no numeric values.

```lus
global print, table

print(table.sum({ 1, 2, 3, 4, 5 }), table.sum({ 1, "skip", "2" }))  --> 15  3
print(table.mean({ 10, 20 }), table.median({ 5, 1, 3, 2, 4 }))  --> 15.0  3
print(table.median({ 1, 2, 3, 4 }), table.mean({}))  --> 2.5  nan

local values = { 2, 4, 4, 4, 5, 5, 7, 9 }
print(table.stdev(values), table.stdev(values, true))  --> 2.0  2.138089935299395
```

`table.sum` of floats, `table.mean`, and `table.stdev` add their values in a fixed order, so the result is the same on every platform. The API entries give the order.

### Transforming arrays

[`table.map(array, func)`](/manual/api#table.map) builds a new array by applying a function to every element, such as converting every field of a column to a number. Element `i` of the result is `func(array[i], i)`, so a call that returns `nil` leaves a gap at that index.

[`table.filter(array, test)`](/manual/api#table.filter) builds a new array of the elements that pass a test. It keeps the elements for which `test(element)` returns a truthy value, in their original order and without gaps. Both functions leave their argument unchanged.

```lus
global print, table

local doubled = table.map({ 1, 2, 3 }, function(x)
    return x * 2
end)

print(doubled[1], doubled[2], doubled[3])  --> 2  4  6

local evens = table.filter({ 1, 2, 3, 4, 5 }, function(x)
    return x % 2 == 0
end)

print(#evens, evens[1], evens[2])  --> 2  2  4
```

[`table.reduce(array, func, initial)`](/manual/api#table.reduce) combines all elements into one value, such as a product, a longest string, or a table of counts. It keeps a running result that starts as `initial`. For each element it calls `func(result, element, index)` and makes the returned value the new running result. If `initial` is absent, the first element is the starting result and the calls begin at the second element. An empty array with no `initial` raises an error.

```lus
global print, table

print(table.reduce({ 1, 2, 3, 4, 5 }, function(acc, x)  --> 15
    return acc + x
end, 0))

print(table.reduce({ 1, 2, 3, 4 }, function(acc, x)  --> 24
    return acc * x
end))

print(
    catch table.reduce(
        {},
        function(acc, x)  --> false  ...: 'reduce' on empty table with no initial value
            return acc
        end
    )
)
```

### Grouping and sorting

[`table.groupby(array, keyfunc)`](/manual/api#table.groupby) divides the elements of an array into groups, such as employees by department. It calls `keyfunc(element)` for each element to get the key of the group that the element belongs to. `groupby` returns a new table that maps each key to an array of the elements with that key, in their original order. A key function that returns `nil` raises the error `table index is nil`.

```lus
global print, table

local people = {
    { name = "Alice", dept = "eng" },
    { name = "Bob", dept = "sales" },
    { name = "Charlie", dept = "eng" },
}

local byDept = table.groupby(people, function(p)
    return p.dept
end)

print(#byDept.eng, #byDept.sales, byDept.eng[2].name)  --> 2  1  Charlie
```

[`table.sortby(array, keyfunc, asc)`](/manual/api#table.sortby) sorts records by one of their properties, such as people by age. Where [`table.sort`](/manual/api#table.sort) takes a function that compares two elements, `sortby` takes a function that returns the value to sort by, called the key. A key function is shorter to write than a comparison. `sortby` calls it once per element, compares the keys with `<`, and sorts the array in place, keeping the relative order of elements with equal keys. It returns nothing. The order is descending when `asc` is `false` and ascending otherwise.

```lus
global print, table

local people = {
    { name = "Charlie", age = 35 },
    { name = "Alice", age = 30 },
    { name = "Bob", age = 25 },
}

table.sortby(people, function(p)
    return p.age
end)

print(people[1].name, people[3].name)  --> Bob  Charlie

table.sortby(people, function(p)
    return p.age
end, false)

print(people[1].name)  --> Charlie
```

### Combining arrays

Data sometimes arrives as separate columns, such as an array of names and an array of ages. A program that needs one entry per person combines the columns with [`table.zip(...)`](/manual/api#table.zip). Entry `i` of the result is the array `{t1[i], t2[i], ...}`, which holds element `i` of each argument. The result is as long as the shortest argument.

[`table.unzip(entries)`](/manual/api#table.unzip) is the reverse. It returns one array per position of the first entry, or nothing for an empty table.

```lus
global print, table

local zipped = table.zip({ "Alice", "Bob", "Charlie" }, { 30, 25 })
print(#zipped, zipped[1][1], zipped[2][2])  --> 2  Alice  25

local names, ages = table.unzip({ { "Alice", 30 }, { "Bob", 25 } })
print(names[2], ages[1])  --> Bob  30
```

### Matrices

A _matrix_ is an array of rows, where every row is an array of the same length. The result of `fromcsv` is a matrix when every row has the same number of fields.

[`table.transpose(matrix)`](/manual/api#table.transpose) turns rows into columns, returning a new matrix in which `result[i][j]` is `matrix[j][i]`. Transposing the rows of a CSV file therefore gives one array per column. Rows of different lengths raise the error `non-rectangular matrix in 'transpose'`.

[`table.reshape(array, rows, cols)`](/manual/api#table.reshape) arranges a flat array into a matrix of `rows` rows and `cols` columns, filling the rows in order, each from left to right. An array whose length differs from `rows * cols` raises an error.

```lus
global print, table

local t = table.transpose({ { 1, 2, 3 }, { 4, 5, 6 } })
print(#t, t[1][2], t[3][1])  --> 3  4  3

local m = table.reshape({ 1, 2, 3, 4, 5, 6 }, 2, 3)
print(#m, m[1][3], m[2][1])  --> 2  3  4
print(catch table.reshape({ 1, 2, 3 }, 2, 2))  --> false  ...: array length 3 does not match 2 x 2
```

## String functions

The `string` and `table` libraries have functions that cut a line into fields, join fields into a line, and remove the spaces around a value.

[`string.split(s, delimiter)`](/manual/api#string.split) cuts a string at every occurrence of a delimiter and returns an array of the pieces. The delimiter may be several characters long and is matched as plain text, so pattern characters such as `.` have no special meaning in it. Two adjacent delimiters produce an empty string between them. A delimiter at either end of the string produces an empty string at that end. An empty delimiter splits the string into its characters.

```lus
global print, string

local parts = string.split("apple,banana,cherry", ",")
print(#parts, parts[1], parts[3])  --> 3  apple  cherry

local dirs = string.split("a//b", "/")
print(#dirs, dirs[2] == "")  --> 3  true

local chars = ("héllo"):split("")
print(#chars, chars[2])  --> 5  é
```

[`table.concat(t, delimiter)`](/manual/api#table.concat) is the reverse, joining the strings and numbers of an array into one string with the delimiter between them. An empty array produces the empty string. A value of any other type raises an error, so a program converts booleans and tables with `tostring` first.

```lus
global print, table, tostring

print(table.concat({ "hello", "world" }, " "))  --> hello world
print(table.concat({ 1, tostring(true), 2.5 }, ","))  --> 1,true,2.5
print(table.concat({}, ",") == "")  --> true
```

Text from a person or a file often has spaces or line breaks around the value. [`string.trim`](/manual/api#string.trim) removes characters from both ends of a string, [`string.ltrim`](/manual/api#string.ltrim) from the start, and [`string.rtrim`](/manual/api#string.rtrim) from the end. Without a second argument, the three functions remove spaces, tabs, line feeds, and carriage returns. With a string as the second argument, they remove the characters in that string.

```lus
global print, string

print("[" .. string.trim("  hello  ") .. "]")  --> [hello]
print("[" .. string.ltrim("  hello  ") .. "]")  --> [hello  ]
print("[" .. string.rtrim("  hello  ") .. "]")  --> [  hello]
print(string.trim("xyhixy", "yx"), string.trim("éhié", "é"))  --> hi  hi
```
