In addition to the compile time attributes, local variables can also be given runtime attributes to control their assignment behavior.

## Basic usage

Runtime attributes are declared as functions and inserted prior to the `local` keyword and the variable name. The function is called with the variable name and value as arguments each time the variable is initialized or assigned within the scope where it is declared.

```lus
local function printvar(name, value)
    print(name, value)
end

local x <printvar> = 10 -- prints "x 10"
x = 20 -- prints "x 20"
```

The return value of the function will be used as the value of the variable, unless it is `nil`, in which case the original value will be used.

```lus
local function modifyvar(name, value)
    return value + 1
end

local x <modifyvar> = 10
assert(x == 11)
```

The attribute will **not** be invoked when assigning `nil` to the variable. For all intents and purposes, assigning `nil` to a variable is equivalent to deleting the variable.

```lus
local function printvar(name, value)
    print(name, value)
end

local x <printvar> = 10 -- prints "x 10"
x = nil -- not invoked; nothing printed
```

## Multiple attributes

Multiple attributes can be separated with commas. They run in declaration order. Each result becomes the argument to the next attribute, and the final result becomes the variable value.

```lus
local function first(name, value)
    print("first", name, value)
    return value + 1
end

local function second(name, value)
    print("second", name, value)
    return value + 2
end

local x <first, second> = 10 -- prints "first x 10", then "second x 11"
assert(x == 13)
```

If using any compile-time attributes (e.g., `const` or `close`), they must be provided first.

```lus nocheck
local function first(name, value)
    print("first", name, value)
end

local x <first, const> = 10 -- error: compile-time attributes must be provided first
local y <const, first> = 10 -- ok
```

## Scope of dispatch

The handler runs on assignments to the variable within the scope where it is declared. When the variable is captured by a nested closure, an assignment through that closure writes the value directly, and the value is used as written.

```lus
local function h(name, value)
    return value
end

local x <h> = 1 -- handler runs on the initializer
local setter = function(v) x = v end
setter(2) -- writes x directly, so x is now 2
```

## Attribute lifetime

An attribute keeps its value reachable for the lifetime of the variable. A metatable with a `__gc` metamethod demonstrates that relationship.

```lus
local printvar = setmetatable({}, {
    __gc = function(self)
        print("printvar is being closed")
    end,
    __call = function(self, name, value)
        print(name, value)
    end
})
local x <printvar> = 10 -- prints "x 10"
printvar = nil
x = 20 -- prints "x 20"
x = nil -- prints "printvar is being closed"
```

## Common patterns

A common pattern is to use a function to generate the attribute, which allows for parameterizing the attribute behavior. In this example, we constrain the type of a local variable to be a number.

```lus nocheck
local function only(expected)
    return function(name, value)
        if type(value) ~= expected then
            error(`Expected $expected, got $(type(value))`)
        end
        return value
    end
end


local x <only "number"> = 10

-- alternatively...
local number = only("number")
local y <number> = 10

y = "hello" -- error: Expected number, got string
```
