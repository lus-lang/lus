The Lus runtime is written in Zig and builds with the Zig compiler alone. The build produces the `lus` executable, the `liblus` embedding library with its header `lus.h`, and the `lus.wasm` WebAssembly module. SQLite, Zstandard, and Brotli are compiled from source as part of the build, so no system libraries are required.

You will need the following tools to compile the runtime:

- The Lus source code, which can be downloaded from its [repository](https://github.com/lus-lang/lus).
- [Zig](https://ziglang.org/download/) 0.17.1. The repository pins it in `mise.toml`, so `mise install` provides the right version.
- Network access on the first build, which fetches the pinned Zstandard and Brotli sources listed in `runtime/build.zig.zon`.

## Building

```bash
git clone https://github.com/lus-lang/lus.git
cd lus/runtime
zig build -Doptimize=ReleaseSafe
```

The `lus` executable is placed in `zig-out/bin`. `ReleaseSafe` keeps the runtime's safety checks while optimizing, which is the recommended mode for running programs. `-Doptimize=ReleaseFast` drops the checks for extra speed. Debug builds work but run slowly, because the debug allocator records a stack trace for every allocation.

### Optional libraries

Four libraries can be left out of a build. Each defaults to included, and a library left out is never registered and its code is compiled out.

| Option | Library |
| --- | --- |
| `-Dnet=false` | The `network` library. |
| `-Dworkers=false` | The `worker` library. |
| `-Dsqlite=false` | `io.sqlite`. |
| `-Darchive=false` | The `vector.archive` compression codecs. |

### Verification

```bash
./zig-out/bin/lus -v
zig build test
```

`zig build test` runs the unit tests of the runtime. Further steps exercise the C embedding interface (`zig build test-embed`), standalone executables (`zig build test-bundle`), and the debugger (`zig build test-debug`, which needs Node). The conformance suite is written for `lus test`.

## Installation

Copy `zig-out/bin/lus` to a directory on your `PATH`:

- On macOS and Linux, you can place it in the `/usr/local/bin` directory.
- On Windows, create a directory for Lus and add that directory to your user `PATH` through Windows Settings.

The executable is self-contained. It carries the standard library, the IANA time zone database, and every tool described in the [CLI](/manual/cli) reference.

## Embedding Lus

```bash
zig build lib -Doptimize=ReleaseSafe
```

This step writes the static library `liblus.a`, the shared `liblus`, and the header `lus.h` under `zig-out`. Each library carries the vendored C code, so a host links one file:

```bash
cc -o myapp myapp.c -Izig-out/include zig-out/lib/liblus.a
```

[Embedding Lus](/manual/guide#embedding-lus) in the Guide introduces the interface, and [Embedding](/manual/embedding) documents it in full.

## WebAssembly

```bash
zig build wasm
```

This step writes `zig-out/wasm/lus.wasm`, a WASI module that exports the embedding interface. The `lus-wasm` package in `packages/wasm` runs it in browsers, web workers, and Node, as described in [WebAssembly](/manual/webassembly).
