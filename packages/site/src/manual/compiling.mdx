Build Lus from source for a platform without a prebuilt archive, for a host that needs a library with parts removed, or to work on the runtime. In every other case, install a release, as [Getting Started](/manual/getting-started) describes.

The Lus runtime is written in Zig, whose compiler is the only tool that the build needs. The build produces the `lus` executable, the `liblus` embedding library with its header `lus.h`, and the `lus.wasm` WebAssembly module. SQLite, Zstandard, and Brotli are compiled from source as part of the build, so the build needs no system libraries.

The build requires the following:

- The Lus source code from its [repository](https://github.com/lus-lang/lus).
- The version of [Zig](https://ziglang.org/download/) that the repository pins in `mise.toml`, which `mise install` provides.
- Network access on the first build, which fetches the pinned Zstandard and Brotli sources listed in `runtime/build.zig.zon`.

## Building

The following commands clone the repository and build the interpreter.

```bash
git clone https://github.com/lus-lang/lus.git
cd lus/runtime
zig build -Doptimize=ReleaseSafe
```

The build writes the `lus` executable to `zig-out/bin`. `ReleaseSafe` optimizes the code and keeps the safety checks of the runtime, so a failed check stops the program with a message. Use it for work on the runtime, where those checks find mistakes. `-Doptimize=ReleaseFast`, the mode of the release archives, removes the checks to make the runtime faster. A build without `-Doptimize` is a debug build, which runs much slower.

### Optional libraries

A build can omit a library that its host never uses, such as the `network` library for a host that never opens a socket, which makes the executable smaller. Each of the following options defaults to `true`. Set to `false`, it omits the code of the library, so the name of the library holds `nil` in a program.

| Option | Library |
| --- | --- |
| `-Dnet=false` | The `network` library. |
| `-Dworkers=false` | The `worker` library. |
| `-Dsqlite=false` | `io.sqlite`. |
| `-Darchive=false` | The `vector.archive` compression codecs. |

`-Djit=false` builds a smaller runtime that interprets every function, for a system that forbids memory that is both writable and executable.

### Verification

The following commands print the version of the new executable and run the unit tests of the runtime.

```bash
./zig-out/bin/lus -v
zig build test
```

Further steps test other parts: `zig build test-embed` tests the C embedding interface, `zig build test-bundle` tests standalone executables, and `zig build test-debug` tests the debugger, which needs Node. The following command runs the conformance suite of the language with `lus test`.

```bash
./zig-out/bin/lus test ../tests/conformance
```

## Installation

Copy `zig-out/bin/lus` to a directory on your `PATH`:

- On macOS and Linux, `/usr/local/bin` is the usual choice.
- On Windows, create a directory for Lus and add that directory to your user `PATH` in Windows Settings.

The executable depends on no other file, because it contains the standard library, the IANA time zone database, and every tool described in the [CLI](/manual/cli) reference.

## Embedding Lus

A host program that embeds Lus links the embedding library, which the `lib` step builds.

```bash
zig build lib -Doptimize=ReleaseSafe
```

This step writes the static library `liblus.a`, the shared library `liblus`, and the header `lus.h` under `zig-out`. Each library includes the C code of SQLite, Zstandard, and Brotli, so a host links one file.

```bash
cc -o myapp myapp.c -Izig-out/include zig-out/lib/liblus.a
```

[Embedding](/manual/embedding) describes the interface. The [C API reference](/manual/api/c) documents every function of `lus.h`.

## WebAssembly

The `wasm` step builds the runtime for browsers and other WebAssembly hosts.

```bash
zig build wasm
```

This step writes `zig-out/wasm/lus.wasm`, a WASI module that exports the embedding interface. The `lus-wasm` package in `packages/wasm` runs it in browsers, web workers, and Node, as [WebAssembly](/manual/webassembly) describes. `mise run wasm` builds the module and copies it into that package as `dist/lus.wasm`.
