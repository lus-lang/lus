Lus 2.0 has one C header, `lus.h`, for programs that embed the runtime. A host creates a state, opens the standard libraries, sets the permission policy, loads and runs code, and exchanges values with it through a stack. Every function that can fail returns a status code, and errors never jump across C frames, so a host written in C, C++, Rust, Zig, or any language with a C foreign function interface handles them with ordinary control flow.

## Building and linking

The embedding library is built from the runtime directory. The step writes the static `liblus.a`, the shared `liblus`, and the header `lus.h` under `zig-out`.

```sh
cd runtime
zig build lib -Doptimize=ReleaseSafe
```

Each library carries the vendored C code of SQLite, Zstandard, and Brotli, so a host links one file.

```sh
cc -o host host.c -Iruntime/zig-out/include runtime/zig-out/lib/liblus.a
```

## A first host

The following host creates a state, registers a C function as a global, runs a script, and reports errors with their traceback.

```c
#include <stdio.h>
#include "lus.h"

/* greet(name) returns "hello, NAME". */
static int greet(lus_State *L) {
  const char *name = lus_tostring(L, 1, NULL);
  if (name == NULL)
    return lus_errorf(L, "bad argument #1 to 'greet' (string expected)");
  if (lus_pushfstring(L, "hello, %s", name) != LUS_OK)
    return lus_error(L);
  return 1;
}

int main(void) {
  lus_State *L = lus_newstate();
  if (L == NULL || lus_openlibs(L) != LUS_OK)
    return 1;

  lus_pushcfunction(L, greet);
  lus_setglobal(L, "greet");

  if (lus_dostring(L, "print(greet('world'))") != LUS_OK) {
    const char *tb = lus_traceback(L);
    fprintf(stderr, "%s\n", lus_tostring(L, -1, NULL));
    if (tb != NULL)
      fprintf(stderr, "%s\n", tb);
    lus_pop(L, 1);
  }

  lus_close(L);
  return 0;
}
```

`lus_newstate` creates a state with no libraries and no permissions, and `lus_openlibs` opens every standard library. A state is used by one thread at a time. `lus_close` runs the remaining finalizers, stops the workers the state started, and frees it.

## The stack

Every value a host or a C function sees lives in a stack slot. Positive indices count from the bottom of the current frame, so index 1 is the first argument of a C function. Negative indices count from the top, so index -1 is the value pushed last. `lus_gettop` returns the number of values in the frame, `lus_settop` grows or shrinks it, and `lus_pop`, `lus_pushvalue`, `lus_insert`, `lus_remove`, and `lus_replace` rearrange it.

Values are read with `lus_toboolean`, `lus_tointeger`, `lus_tonumber`, `lus_tostring`, `lus_tobytes` for vectors, `lus_touserdata`, and `lus_tolight`, and their types are inspected with `lus_type`. Strings are well formed WTF-8 and followed by a zero byte, and `lus_tostring` returns `NULL` for a value that is not a string. Values are pushed with `lus_pushnil`, `lus_pushboolean`, `lus_pushinteger`, `lus_pushnumber`, `lus_pushstring`, `lus_pushlstring`, `lus_pushfstring`, `lus_pushbytes` for vectors, `lus_pushlight` for raw host pointers, and `lus_newtable`.

A push that allocates returns a status, and it always pushes exactly one value: the new value on success and the error value on failure. The stack therefore changes by the documented amount in every case, and a function that checks a status can return `lus_error(L)` immediately.

## Tables and globals

`lus_getfield`, `lus_setfield`, `lus_gettable`, `lus_settable`, `lus_getglobal`, `lus_setglobal`, and `lus_len` honor metamethods, so they return a status. `lus_rawget`, `lus_rawgeti`, `lus_rawset`, `lus_rawseti`, and `lus_rawlen` bypass metamethods. `lus_next` traverses a table, starting from a nil key.

## Calling Lus from C

A call pushes the function, then its arguments, then calls `lus_pcall` with the number of arguments and the number of results to keep, or `LUS_MULTRET` for all of them. On success the function and its arguments are replaced by the results. On failure they are replaced by the error value and the status code is returned. `lus_traceback` returns the stack traceback of the last error that `lus_pcall` caught.

```c
lus_getglobal(L, "greet");
lus_pushstring(L, "from C");
if (lus_pcall(L, 1, 1) == LUS_OK)
  printf("%s\n", lus_tostring(L, -1, NULL));
lus_pop(L, 1);
```

`lus_load` compiles source text or a binary chunk and pushes it as a function, `lus_loadfile` loads a file, and `lus_dostring` and `lus_dofile` load and run in one step, leaving the results on the stack. The status codes are `LUS_OK`, `LUS_ERRRUN` for runtime errors, `LUS_ERRSYNTAX` for syntax errors, `LUS_ERRMEM` for allocation failures, and `LUS_ERRFILE` for files that cannot be read.

## Writing C functions

A C function receives its arguments at indices 1 through `lus_gettop(L)`, pushes its results, and returns how many it pushed. To raise an error it returns `LUS_ERROR`, which is what `lus_error` returns after taking the top value as the error. `lus_errorstr` and `lus_errorf` raise a message prefixed with the position of the calling Lus code.

`lus_pushcclosure` creates a C function with upvalues, which the function reads with `lus_getupvalue`. `lus_stringify` converts any value to a string the way `tostring` does, honoring `__tostring` and `__name`.

## Userdata

`lus_newuserdata` pushes a block of host memory that the collector manages. `lus_newmetatable` creates or fetches a metatable registered under a type name, `lus_setmetatable` attaches it, and `lus_toudata` returns the block only when the value carries the metatable of the expected name. A `__gc` field in the metatable becomes the finalizer of the object.

```c
typedef struct Counter { lus_Integer value; } Counter;

static int counter_new(lus_State *L) {
  Counter *c = lus_newuserdata(L, sizeof *c);
  if (c == NULL)
    return lus_error(L);
  c->value = lus_tointeger(L, 1, NULL);
  lus_getmetatable(L, "Counter");
  if (lus_setmetatable(L, -2) != LUS_OK)
    return lus_error(L);
  return 1;
}

static int counter_bump(lus_State *L) {
  Counter *c = lus_toudata(L, 1, "Counter");
  if (c == NULL)
    return lus_errorf(L, "bad argument #1 to 'bump' (Counter expected)");
  lus_pushinteger(L, ++c->value);
  return 1;
}
```

## References

A value that the host keeps between calls, such as a callback, is held through a reference. `lus_ref` pops a value and returns a stable integer handle, `lus_getref` pushes the value again, and `lus_unref` releases the handle.

```c
static int callback = LUS_NOREF;

/* onevent(fn) stores fn for later. */
static int on_event(lus_State *L) {
  lus_pushvalue(L, 1);
  callback = lus_ref(L);
  return 0;
}

static void fire(lus_State *L) {
  lus_getref(L, callback);
  lus_pushstring(L, "ready");
  if (lus_pcall(L, 1, 0) != LUS_OK)
    lus_pop(L, 1);
}
```

## Permissions

A state starts with no permissions. The host decides what scripts may do before they run, with the same capability names and value syntax as [`pledge`](/manual/acquis-10).

- `lus_grant(L, spec)` grants a capability, such as `"fs:read=/srv/data/*"` or `"network"`.
- `lus_reject(L, name)` rejects a capability permanently.
- `lus_seal(L)` freezes the permission set.

Once the host grants anything, scripts can pledge only what those grants cover. A host that wants to decide pledges interactively installs a request hook with `lus_onrequest`. The hook runs when a script pledges a capability that the host has neither granted nor rejected, and it returns 1 to allow the grant.

```c
#include <stdio.h>
#include "lus.h"

static int ask(void *ud, lus_State *L, const char *capability, const char *value) {
  (void)ud;
  (void)L;
  printf("allow %s=%s? ", capability, value ? value : "");
  return getchar() == 'y';
}

void configure(lus_State *L) {
  lus_grant(L, "fs:read=/srv/data/*");
  lus_reject(L, "exec");
  lus_onrequest(L, ask, NULL);
}
```

An extension declares its own capabilities with `lus_defcapability`, and its C functions check them with `lus_require`, which pushes the standard permission error on failure, or `lus_allowed`, which only answers. Scripts then pledge the new capability like any built-in one. The value kind of a capability decides how a granted value matches a requested one: `LUS_CAP_NONE` takes no value, `LUS_CAP_PATH` matches canonical path globs, `LUS_CAP_HOST` matches hosts with an optional port and path, `LUS_CAP_PATTERN` matches a glob over an opaque string, and `LUS_CAP_CUSTOM` calls a matcher function.

```c
static const char *const store_subs[] = {"read", "write", NULL};

/* store.get(key) requires store:read for the key. */
static int store_get(lus_State *L) {
  const char *key = lus_tostring(L, 1, NULL);
  if (key == NULL)
    return lus_errorf(L, "bad argument #1 to 'get' (string expected)");
  if (lus_require(L, "store:read", key) != LUS_OK)
    return lus_error(L);
  return lus_pushfstring(L, "value of %s", key) == LUS_OK ? 1 : lus_error(L);
}

static void open_store(lus_State *L) {
  lus_Capability cap = {0};
  cap.name = "store";
  cap.subcapabilities = store_subs;
  cap.kind = LUS_CAP_PATTERN;
  lus_defcapability(L, &cap);
  /* ... register store.get ... */
}
```

With `lus_grant(L, "store:read=users/*")`, the script call `store.get("users/ada")` succeeds and `store.get("secrets/key")` raises `permission "store:read" denied for 'secrets/key'`.

## Motivation

### Errors as values

Returning a status from every fallible call keeps control flow inside the host's own language. A host never needs a protected trampoline to survive an error, a failed push leaves the error where the result would have been, and bindings for other languages wrap each call directly.

### Capabilities owned by the host

The host decides what embedded scripts may do, using the same capability vocabulary that scripts use with `pledge`. Extensions add their own capabilities through the same registry as the runtime, so a script sees one uniform permission system and an embedding application can extend it without special cases.

### One interface everywhere

The same header is the interface of the native libraries and of the [WebAssembly module](/manual/acquis-42), which exports every function of `lus.h`. A host written against it runs in a native process and in a browser alike.
