Embedding puts the Lus runtime inside another program, so that the users of that program can script it. For example, a game can run its levels as Lus scripts, an editor can load plugins, and a server can read its configuration as code. A _host_ is a program that embeds the runtime through the C header `lus.h` and the library `liblus`. The host creates a state, opens the standard libraries, decides which permissions scripts may hold, loads and runs code, and exchanges values with that code through a stack.

Every function of the interface that can fail returns a status code, and an error never jumps out of a C function. A host written in C, C++, Rust, Zig, or any language that can call C therefore handles errors with ordinary `if` statements.

The [C API reference](/manual/api/c) documents every function, type, and constant of `lus.h`. This page describes how the parts fit together.

## Building and linking

Every [release archive](/manual/releases#archive-layout) contains the embedding library and the header. To build them from source, run the `lib` step in the runtime directory. The step writes the static library `liblus.a`, the shared library `liblus`, and the header `lus.h` under `zig-out`.

```sh
cd runtime
zig build lib -Doptimize=ReleaseSafe
```

Each library includes the C code of SQLite, Zstandard, and Brotli, so a host links one file.

```sh
cc -o host host.c -Iruntime/zig-out/include runtime/zig-out/lib/liblus.a
```

[Compiling Lus](/manual/compiling) describes the toolchain and the options that leave libraries out of the build.

## A first host

The following host creates a state, registers a C function as a global, runs a script, and reports an error with its traceback.

```c
#include <stdio.h>
#include "lus.h"

/* greet(name) returns "hello, NAME". */
static int greet(lus_State *L) {
  const char *name = lus_tostring(L, 1, NULL);
  if (name == NULL)
    return lus_errorf(L, "bad argument #1 to 'greet' (string expected)");
  if (lus_pushfstring(L, "hello, %s", name) != LUS_OK)
    return lus_error(L);
  return 1;
}

int main(void) {
  lus_State *L = lus_newstate();
  if (L == NULL || lus_openlibs(L) != LUS_OK)
    return 1;

  lus_pushcfunction(L, greet);
  lus_setglobal(L, "greet");

  if (lus_dostring(L, "print(greet('world'))") != LUS_OK) {
    const char *tb = lus_traceback(L);
    fprintf(stderr, "%s\n", lus_tostring(L, -1, NULL));
    if (tb != NULL)
      fprintf(stderr, "%s\n", tb);
    lus_pop(L, 1);
  }

  lus_close(L);
  return 0;
}
```

A _state_ is one independent instance of the runtime, with its own globals and its own memory. [`lus_newstate`](/manual/api/c#lus_newstate) creates a state with no libraries and no permissions, and returns `NULL` when memory runs out. [`lus_openlibs`](/manual/api/c#lus_openlibs) opens every standard library into the global table. Only one thread may use a state at a time. [`lus_close`](/manual/api/c#lus_close) closes the detached coroutines that have not ended, runs the remaining finalizers, stops the workers that the state started, and frees the state.

## The stack

C code never holds a Lus value directly, because the garbage collector must know every value that is in use. The host and its C functions instead work on a _stack_ of values that the state owns: a function pushes values onto the stack, reads them by index, and pops them. Positive indices count from the bottom of the current frame, so index 1 is the first argument of a C function. Negative indices count from the top, so index -1 is the value pushed last. `lus_gettop` returns the number of values in the frame, `lus_settop` grows or shrinks it, and `lus_pop`, `lus_pushvalue`, `lus_insert`, `lus_remove`, and `lus_replace` rearrange it.

Values are read with `lus_toboolean`, `lus_tointeger`, `lus_tonumber`, `lus_tostring`, `lus_tobytes` for vectors, `lus_touserdata`, and `lus_tolight`, and `lus_type` returns the type of a slot as one of the `LUS_T` constants. Strings are well formed WTF-8 followed by a zero byte. `lus_tostring` returns `NULL` for a value that is not a string and converts no other type.

Values are pushed with `lus_pushnil`, `lus_pushboolean`, `lus_pushinteger`, `lus_pushnumber`, `lus_pushstring`, `lus_pushlstring`, `lus_pushfstring`, `lus_pushbytes` for vectors, `lus_pushlight` for raw host pointers, and `lus_newtable`.

A push that allocates memory returns a status, and it always pushes exactly one value: the new value on success and the error object on failure. Because the error object is then on top of the stack, a C function that sees a failed status can raise that error by returning `lus_error(L)`.

## Tables and globals

A host reads the results and the configuration of a script, and gives it data, through tables and globals. `lus_getfield`, `lus_setfield`, `lus_gettable`, `lus_settable`, `lus_getglobal`, `lus_setglobal`, and `lus_len` behave as the same operations do in Lus code, metamethods included, so they can fail and they return a status. `lus_rawget`, `lus_rawgeti`, `lus_rawset`, `lus_rawseti`, and `lus_rawlen` skip metamethods. `lus_next` visits the entries of a table one at a time, starting from a nil key.

The following fragment reads a field and checks the status, which is `LUS_ERRRUN` with the message `attempt to index a nil value` when the slot holds nil.

```c
if (lus_getfield(L, 1, "width") != LUS_OK)
  return lus_error(L);
lus_Integer width = lus_tointeger(L, -1, NULL);
lus_pop(L, 1);
```

## Calling Lus from C

A host calls a Lus function to run an event handler, a callback, or an entry point that a script defined. To make the call, the host pushes the function, then its arguments, then calls [`lus_pcall`](/manual/api/c#lus_pcall) with the number of arguments and the number of results to keep, or `LUS_MULTRET` for all of them. On success the results replace the function and its arguments. On failure the error object replaces them, and `lus_pcall` returns the status code. [`lus_traceback`](/manual/api/c#lus_traceback) returns the stack traceback of the last error that `lus_pcall` caught, or `NULL` when that error had none. The following fragment calls the global function `greet` with one argument and prints its result.

```c
lus_getglobal(L, "greet");
lus_pushstring(L, "from C");
if (lus_pcall(L, 1, 1) == LUS_OK)
  printf("%s\n", lus_tostring(L, -1, NULL));
lus_pop(L, 1);
```

`lus_load` compiles source text or a binary chunk and pushes it as a function, and `lus_loadfile` does the same for a file. The host itself reads the file, so no permission of the state is checked. `lus_dostring` and `lus_dofile` load and run in one step and leave the results on the stack.

The status codes are the following.

| Code | Meaning |
| --- | --- |
| `LUS_OK` | Success. |
| `LUS_ERRRUN` | A runtime error. |
| `LUS_ERRSYNTAX` | A syntax error while compiling. |
| `LUS_ERRMEM` | The allocator failed. |
| `LUS_ERRFILE` | A file could not be opened or read. |

A script that uses [detached coroutines](/manual/concurrency), for example to serve network connections, needs the host to keep running them after the call that started them returns. [`lus_runpending`](/manual/api/c#lus_runpending) with a nonzero `wait` runs the detached coroutines until none is left, as the `lus` command does after the main chunk. With `wait` zero it runs the coroutines that are ready and returns, so a host with an event loop of its own can call it on every turn of the loop. [`lus_pending`](/manual/api/c#lus_pending) returns the number of detached coroutines that have not ended.

## Writing C functions

A C function is how a host offers its own features to scripts, as `greet` does in the first host. It receives its arguments at indices 1 through `lus_gettop(L)`, pushes its results, and returns how many it pushed. To raise an error it returns `LUS_ERROR`, which is what [`lus_error`](/manual/api/c#lus_error) returns after it takes the top value as the error object. `lus_errorstr` and `lus_errorf` raise a message prefixed with the position of the calling Lus code, as in `(dostring):1: bad argument #1 to 'greet' (string expected)`.

A C function sometimes needs data of its own, such as a pointer to the object it acts on. `lus_pushcclosure` pops values from the stack and creates a C function that keeps them. The function reads the kept values back with `lus_getupvalue`, where an _upvalue_ is one of the values that a function keeps. `lus_stringify` converts any value to a string as `tostring` does, which includes calling `__tostring`.

## Userdata

A _userdata_ is a block of host memory that scripts hold as a value. It is how a host gives scripts an object of its own, such as a file, a sprite, or a database connection, with methods and automatic cleanup. [`lus_newuserdata`](/manual/api/c#lus_newuserdata) pushes a new block, aligned to 8 bytes, which the garbage collector frees when no script refers to it. A metatable gives the userdata its type and its methods. `lus_newmetatable` creates or fetches a metatable registered under a type name, `lus_setmetatable` attaches a metatable to a value, and `lus_toudata` returns the block only when the value has the metatable of the expected name, which protects a method against a value of another type. A `__gc` field in the metatable is the finalizer of the object. The finalizer receives the object as its only argument and runs at most once, after the object becomes unreachable or when the state closes.

The following functions implement a counter type with a constructor and a `bump` method.

```c
typedef struct Counter { lus_Integer value; } Counter;

static int counter_new(lus_State *L) {
  Counter *c = lus_newuserdata(L, sizeof *c);
  if (c == NULL)
    return lus_error(L);
  c->value = lus_tointeger(L, 1, NULL);
  lus_getmetatable(L, "Counter");
  if (lus_setmetatable(L, -2) != LUS_OK)
    return lus_error(L);
  return 1;
}

static int counter_bump(lus_State *L) {
  Counter *c = lus_toudata(L, 1, "Counter");
  if (c == NULL)
    return lus_errorf(L, "bad argument #1 to 'bump' (Counter expected)");
  lus_pushinteger(L, ++c->value);
  return 1;
}

/* Registers the Counter type. The host calls it once and gets a status. */
static int open_counter(lus_State *L) {
  if (lus_newmetatable(L, "Counter") == LUS_ERROR)
    return LUS_ERRMEM;
  lus_newtable(L, 0, 1);
  lus_pushcfunction(L, counter_bump);
  lus_setfield(L, -2, "bump");
  lus_setfield(L, -2, "__index");
  lus_pop(L, 1);
  lus_pushcfunction(L, counter_new);
  return lus_setglobal(L, "Counter");
}
```

After `open_counter`, the script `local c = Counter(41) print(c:bump(), c:bump())` prints `42` and `43`.

## References

The stack of a C function is gone when the function returns, so a host needs another way to keep a Lus value between calls, such as a callback that a script registered. A _reference_ is an integer that names a value which the state keeps alive for the host. [`lus_ref`](/manual/api/c#lus_ref) pops a value and returns a reference to it, or `LUS_NOREF` when the value is nil. `lus_getref` pushes the value again. `lus_unref` releases the reference, after which the state may give the same number to another value. The following host stores a callback in `on_event` and calls it later from `fire`. A second call to `on_event` releases the reference to the previous callback before it stores the new one.

```c
static int callback = LUS_NOREF;

/* on_event(fn) stores fn for later. */
static int on_event(lus_State *L) {
  lus_unref(L, callback);
  lus_pushvalue(L, 1);
  callback = lus_ref(L);
  if (callback == LUS_ERROR) {
    callback = LUS_NOREF;
    return lus_error(L);
  }
  return 0;
}

static void fire(lus_State *L) {
  lus_getref(L, callback);
  lus_pushstring(L, "ready");
  if (lus_pcall(L, 1, 0) != LUS_OK)
    lus_pop(L, 1);
}
```

## Permissions

A host usually runs scripts that its own author did not write, so it decides what those scripts may reach. A state starts with no [permissions](/manual/permissions), and the host sets its policy before any script runs, with the same capability names and values that `pledge` takes.

- [`lus_grant`](/manual/api/c#lus_grant) grants a capability, such as `"fs:read=/srv/data/*"` or `"network"`.
- [`lus_reject`](/manual/api/c#lus_reject) rejects a capability for the life of the state, so every later grant of it fails.
- [`lus_seal`](/manual/api/c#lus_seal) freezes the permissions, as `pledge("seal")` does in a script.

Once the host grants anything, a script can pledge only what those grants cover, and `pledge` returns `false` for everything else. A script that pledges a rejected capability raises an error such as `permission "exec" was rejected`.

A host can also decide each pledge at the moment a script makes it, for example by asking the user. Such a host installs a request hook with [`lus_onrequest`](/manual/api/c#lus_onrequest). The hook runs when a script pledges a capability that the host has neither granted nor rejected. It receives the capability, such as `"fs:read"`, and the requested value, or `NULL` when there is none, and it returns 1 to allow the grant. The following host grants one directory, rejects `exec`, and asks on the terminal about every other pledge.

```c
#include <stdio.h>
#include "lus.h"

static int ask(void *ud, lus_State *L, const char *capability, const char *value) {
  char answer[16];
  (void)ud;
  (void)L;
  printf("allow %s=%s? ", capability, value ? value : "");
  fflush(stdout);
  return fgets(answer, sizeof answer, stdin) != NULL && answer[0] == 'y';
}

void configure(lus_State *L) {
  lus_grant(L, "fs:read=/srv/data/*");
  lus_reject(L, "exec");
  lus_onrequest(L, ask, NULL);
}
```

### Capabilities of an extension

The functions that a host adds can reach things that no built-in permission covers, such as the documents of an application. An extension therefore declares its own capabilities with [`lus_defcapability`](/manual/api/c#lus_defcapability). Its C functions check them with `lus_require`, which pushes the standard permission error and returns `LUS_ERRRUN` on failure, or with `lus_allowed`, which answers without raising. Scripts then pledge the new capability as they pledge a built-in one.

The value kind of a capability decides how a granted value matches a requested one.

| Kind | Matching |
| --- | --- |
| `LUS_CAP_NONE` | The capability takes no value. |
| `LUS_CAP_PATH` | Canonical file system path globs. |
| `LUS_CAP_HOST` | A host with an optional port and path glob, as in `host:port/path`. |
| `LUS_CAP_PATTERN` | A glob over an opaque string. |
| `LUS_CAP_CUSTOM` | A matcher function that the extension supplies decides. |

The following extension declares the capability `store` with the subcapabilities `read` and `write`, and checks `store:read` for every key it reads.

```c
static const char *const store_subs[] = {"read", "write", NULL};

/* store.get(key) requires store:read for the key. */
static int store_get(lus_State *L) {
  const char *key = lus_tostring(L, 1, NULL);
  if (key == NULL)
    return lus_errorf(L, "bad argument #1 to 'get' (string expected)");
  if (lus_require(L, "store:read", key) != LUS_OK)
    return lus_error(L);
  return lus_pushfstring(L, "value of %s", key) == LUS_OK ? 1 : lus_error(L);
}

static void open_store(lus_State *L) {
  lus_Capability cap = {0};
  cap.name = "store";
  cap.subcapabilities = store_subs;
  cap.kind = LUS_CAP_PATTERN;
  lus_defcapability(L, &cap);
  lus_newtable(L, 0, 1);
  lus_pushcfunction(L, store_get);
  lus_setfield(L, -2, "get");
  lus_setglobal(L, "store");
}
```

With `lus_grant(L, "store:read=users/*")`, the script call `store.get("users/ada")` succeeds, and `store.get("secrets/key")` raises `permission "store:read" denied for 'secrets/key'`.
