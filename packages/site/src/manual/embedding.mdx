Embedding puts the Lus runtime inside another program, so that the users of that program can script it. A game can run its levels as Lus scripts. An editor can load plugins. A server can read its configuration as code. A _host_ is a program that embeds the runtime. It includes the C header `lus.h`, which declares the interface. It links the library `liblus`, which contains the runtime. The host creates a state, opens the standard libraries, sets the permissions that scripts may hold, and runs code. The host and the code exchange values on a stack.

Every function of the interface that can fail returns a status code. Lus reports every error this way, so control always returns to the C code that made the call. A host written in C, C++, Rust, Zig, or any other language that can call C therefore handles errors with ordinary `if` statements.

The [C API reference](/manual/api/c) documents every function, type, and constant of `lus.h`.

## Building and linking

Every [release archive](/manual/releases#archive-layout) contains the embedding library and the header. To build them from source, run the `lib` step in the runtime directory. The step writes the static library `liblus.a`, the shared library `liblus`, and the header `lus.h` under `zig-out`.

```sh
cd runtime
zig build lib -Doptimize=ReleaseSafe
```

Each library includes the C code of SQLite, Zstandard, and Brotli, so a host links one file. The following command compiles `host.c` and links it with the static library.

```sh
cc -o host host.c -Iruntime/zig-out/include runtime/zig-out/lib/liblus.a
```

[Compiling Lus](/manual/compiling) describes the toolchain and the options that leave libraries out of the build.

## A first host

The following host gives scripts a `greet` function and runs a script that calls it. If the script fails, the host prints the error and its traceback.

```c
#include <stdio.h>
#include "lus.h"

/* greet(name) returns "hello, NAME". */
static int greet(lus_State *L) {
  const char *name = lus_tostring(L, 1, NULL);
  if (name == NULL)
    return lus_errorf(L, "bad argument #1 to 'greet' (string expected)");
  if (lus_pushfstring(L, "hello, %s", name) != LUS_OK)
    return lus_error(L);
  return 1;
}

int main(void) {
  lus_State *L = lus_newstate();
  if (L == NULL || lus_openlibs(L) != LUS_OK)
    return 1;

  lus_pushcfunction(L, greet);
  lus_setglobal(L, "greet");

  if (lus_dostring(L, "print(greet('world'))") != LUS_OK) {
    const char *tb = lus_traceback(L);
    fprintf(stderr, "%s\n", lus_tostring(L, -1, NULL));
    if (tb != NULL)
      fprintf(stderr, "%s\n", tb);
    lus_pop(L, 1);
  }

  lus_close(L);
  return 0;
}
```

A _state_ is one independent instance of the runtime, with its own globals and its own memory. [`lus_newstate`](/manual/api/c#lus_newstate) creates a state with no libraries and no permissions. It returns `NULL` when memory runs out. [`lus_openlibs`](/manual/api/c#lus_openlibs) adds every standard library to the globals of the state. Only one thread may use a state at a time. [`lus_close`](/manual/api/c#lus_close) frees the state. Before that, it closes the detached coroutines that have not ended, runs the remaining finalizers, and stops the workers that the state started.

## The stack

The garbage collector must be able to find every value that is in use, so C code never holds a Lus value directly. The state owns a _stack_ of values. The host and its C functions push values onto the stack, read them by index, and pop them. Each call of a C function has its own _frame_, which is the part of the stack that holds its arguments and the values it pushes. Positive indices count from the bottom of the current frame, so index 1 is the first argument of a C function. Negative indices count from the top, so index -1 is the value pushed last. `lus_gettop` returns the number of values in the frame. `lus_settop` grows or shrinks the frame. `lus_pop`, `lus_pushvalue`, `lus_insert`, `lus_remove`, and `lus_replace` rearrange it.

The functions that read a value are `lus_toboolean`, `lus_tointeger`, `lus_tonumber`, `lus_tostring`, `lus_tobytes` for vectors, `lus_touserdata`, and `lus_tolight`. `lus_type` returns the type of a stack slot as one of the `LUS_T` constants. A string is well formed WTF-8 followed by a zero byte. `lus_tostring` returns `NULL` for every value that is not a string, numbers included.

The functions that push a value are `lus_pushnil`, `lus_pushboolean`, `lus_pushinteger`, `lus_pushnumber`, `lus_pushstring`, `lus_pushlstring`, `lus_pushfstring`, `lus_pushbytes` for vectors, `lus_pushlight` for raw host pointers, and `lus_newtable`.

A push that allocates memory returns a status. It always pushes exactly one value, which is the new value on success and the error object on failure. After a failure the error object is on top of the stack, so a C function can raise that error by returning `lus_error(L)`.

## Tables and globals

A script stores its results and its configuration in tables and globals, where the host reads them. The host gives data to a script in the same way. `lus_getfield`, `lus_setfield`, `lus_gettable`, `lus_settable`, `lus_getglobal`, `lus_setglobal`, and `lus_len` behave as the same operations do in Lus code. They call metamethods, which can raise errors, so each of them returns a status. `lus_rawget`, `lus_rawgeti`, `lus_rawset`, `lus_rawseti`, and `lus_rawlen` skip metamethods. `lus_next` returns the entries of a table one at a time. The traversal starts from a nil key.

The following code reads the field `width` of the value at index 1. If that value is nil, the status is `LUS_ERRRUN` with the message `attempt to index a nil value`.

```c
if (lus_getfield(L, 1, "width") != LUS_OK)
  return lus_error(L);
lus_Integer width = lus_tointeger(L, -1, NULL);
lus_pop(L, 1);
```

## Calling Lus from C

A host calls a Lus function to run an event handler, a callback, or an entry point that a script defined. The host pushes the function, then its arguments. It then calls [`lus_pcall`](/manual/api/c#lus_pcall) with the number of arguments and the number of results to keep. `LUS_MULTRET` keeps all the results. On success, the results replace the function and its arguments on the stack. On failure, the error object replaces them and `lus_pcall` returns the status code of the error. [`lus_traceback`](/manual/api/c#lus_traceback) returns the stack traceback of the last error that `lus_pcall` caught, or `NULL` when that error had none. The following code calls the global function `greet` with one argument and prints its result.

```c
lus_getglobal(L, "greet");
lus_pushstring(L, "from C");
if (lus_pcall(L, 1, 1) == LUS_OK)
  printf("%s\n", lus_tostring(L, -1, NULL));
lus_pop(L, 1);
```

`lus_load` compiles source text or a binary chunk and pushes the result as a function. `lus_loadfile` does the same for a file. The host process reads the file, so Lus checks no permission of the state. `lus_dostring` and `lus_dofile` load and run code in one call. The results stay on the stack.

The following table lists the status codes.

| Code | Meaning |
| --- | --- |
| `LUS_OK` | Success. |
| `LUS_ERRRUN` | A runtime error. |
| `LUS_ERRSYNTAX` | A syntax error while compiling. |
| `LUS_ERRMEM` | The allocator failed. |
| `LUS_ERRFILE` | A file could not be opened or read. |

A script can start [detached coroutines](/manual/concurrency), for example to serve network connections. These coroutines are still running when the call that started them returns, so the host must keep running them. [`lus_runpending`](/manual/api/c#lus_runpending) with a nonzero `wait` runs the detached coroutines until every one has ended, as the `lus` command does after the main chunk. With a `wait` of zero, it runs the coroutines that are ready and then returns. A host with its own event loop can call it this way on every iteration of the loop. [`lus_pending`](/manual/api/c#lus_pending) returns the number of detached coroutines that have not ended.

## Writing C functions

A host offers its own features to scripts as C functions, such as `greet` in [A first host](#a-first-host). The arguments of a C function are at indices 1 to `lus_gettop(L)`. The function pushes its results and returns their count. To raise an error, the function returns `LUS_ERROR`. [`lus_error`](/manual/api/c#lus_error) takes the value on top of the stack as the error object and returns `LUS_ERROR`, so a C function raises an error with `return lus_error(L)`. `lus_errorstr` and `lus_errorf` raise a message. They prefix the message with the position of the Lus code that called the C function, as in `(dostring):1: bad argument #1 to 'greet' (string expected)`.

A C function sometimes needs data of its own, such as a pointer to the object it operates on. `lus_pushcclosure` pops values from the stack and creates a C function that keeps them. Each kept value is called an _upvalue_. The function reads its upvalues with `lus_getupvalue`.

`lus_stringify` converts any value to a string as `tostring` does. It calls the `__tostring` metamethod when the value has one.

## Userdata

A _userdata_ is a block of host memory that scripts hold as a value. A host uses userdata to give scripts an object of its own, such as a file, a sprite, or a database connection. The object can have methods. Lus frees it automatically. [`lus_newuserdata`](/manual/api/c#lus_newuserdata) pushes a new block, aligned to 8 bytes. The garbage collector frees the block when no script refers to it.

A metatable gives the userdata its type and its methods. `lus_newmetatable` pushes the metatable that is registered under a type name. It creates the metatable first when the name is new. `lus_setmetatable` attaches a metatable to a value. `lus_toudata` returns the block only when the value has the metatable of the expected name. A method calls it to reject a value of another type. A `__gc` field in the metatable is the finalizer of the object. The finalizer receives the object as its only argument. It runs at most once, after the object becomes unreachable or when the state closes.

The following functions implement a counter type with a constructor and a `bump` method.

```c
typedef struct Counter { lus_Integer value; } Counter;

static int counter_new(lus_State *L) {
  Counter *c = lus_newuserdata(L, sizeof *c);
  if (c == NULL)
    return lus_error(L);
  c->value = lus_tointeger(L, 1, NULL);
  lus_getmetatable(L, "Counter");
  if (lus_setmetatable(L, -2) != LUS_OK)
    return lus_error(L);
  return 1;
}

static int counter_bump(lus_State *L) {
  Counter *c = lus_toudata(L, 1, "Counter");
  if (c == NULL)
    return lus_errorf(L, "bad argument #1 to 'bump' (Counter expected)");
  lus_pushinteger(L, ++c->value);
  return 1;
}

/* Registers the Counter type. The host calls it once and gets a status. */
static int open_counter(lus_State *L) {
  if (lus_newmetatable(L, "Counter") == LUS_ERROR)
    return LUS_ERRMEM;
  lus_newtable(L, 0, 1);
  lus_pushcfunction(L, counter_bump);
  lus_setfield(L, -2, "bump");
  lus_setfield(L, -2, "__index");
  lus_pop(L, 1);
  lus_pushcfunction(L, counter_new);
  return lus_setglobal(L, "Counter");
}
```

After `open_counter`, the script `local c = Counter(41) print(c:bump(), c:bump())` prints `42` and `43`.

## References

The values in the frame of a C function are discarded when the function returns. A host therefore needs another way to keep a Lus value between calls, such as a callback that a script registered. A _reference_ is an integer that identifies a value. The state keeps the value alive for the host until the host releases the reference. [`lus_ref`](/manual/api/c#lus_ref) pops a value and returns a reference to it, or `LUS_NOREF` when the value is nil. `lus_getref` pushes the value of a reference. `lus_unref` releases a reference. The state may then give the same number to another value.

The following host stores a callback in `on_event` and calls it later from `fire`. A second call to `on_event` releases the reference to the previous callback before it stores the new one.

```c
static int callback = LUS_NOREF;

/* on_event(fn) stores fn for later. */
static int on_event(lus_State *L) {
  lus_unref(L, callback);
  lus_pushvalue(L, 1);
  callback = lus_ref(L);
  if (callback == LUS_ERROR) {
    callback = LUS_NOREF;
    return lus_error(L);
  }
  return 0;
}

static void fire(lus_State *L) {
  lus_getref(L, callback);
  lus_pushstring(L, "ready");
  if (lus_pcall(L, 1, 0) != LUS_OK)
    lus_pop(L, 1);
}
```

## Permissions

A host usually runs scripts that its own author did not write, so the host limits what those scripts can do. A state starts with no [permissions](/manual/permissions). The host sets them before any script runs, with the same names and values that `pledge` takes. `lus.h` calls a permission a _capability_, which is why the names of its functions and types contain `capability`.

- [`lus_grant`](/manual/api/c#lus_grant) grants a permission, such as `"fs:read=/srv/data/*"` or `"network"`.
- [`lus_reject`](/manual/api/c#lus_reject) rejects a permission for the life of the state, so every later grant of it fails.
- [`lus_seal`](/manual/api/c#lus_seal) seals the permissions, as `pledge("seal")` does in a script.

Once the host grants anything, a script can pledge only what those grants cover. `pledge` returns `false` for everything else. Pledging a rejected permission raises an error such as `permission "exec" was rejected`.

A host can also decide each pledge when a script makes it, for example by asking the user. Such a host installs a _request hook_ with [`lus_onrequest`](/manual/api/c#lus_onrequest). Lus calls the hook when a script pledges a permission that the host has neither granted nor rejected. The hook receives the name of the permission, such as `"fs:read"`. It also receives the requested value, which is `NULL` when the pledge has none. The hook returns 1 to allow the grant. The following host grants read access to one directory and rejects `exec`. For every other pledge, it prompts the person at the terminal.

```c
#include <stdio.h>
#include "lus.h"

static int ask(void *ud, lus_State *L, const char *capability, const char *value) {
  char answer[16];
  (void)ud;
  (void)L;
  printf("allow %s=%s? ", capability, value ? value : "");
  fflush(stdout);
  return fgets(answer, sizeof answer, stdin) != NULL && answer[0] == 'y';
}

void configure(lus_State *L) {
  lus_grant(L, "fs:read=/srv/data/*");
  lus_reject(L, "exec");
  lus_onrequest(L, ask, NULL);
}
```

### Capabilities of an extension

The functions that a host adds can give scripts access to things that no built-in permission covers, such as the documents of an application. An extension therefore declares its own permissions with [`lus_defcapability`](/manual/api/c#lus_defcapability). Its C functions check a permission with `lus_require` or `lus_allowed`. When the check fails, `lus_require` pushes the standard permission error and returns `LUS_ERRRUN`. `lus_allowed` returns 1 when the script holds the permission and 0 otherwise. It never raises an error. Scripts pledge the new permission as they pledge a built-in one.

The _value kind_ of a permission determines how Lus compares a granted value with a requested one.

| Kind | Matching |
| --- | --- |
| `LUS_CAP_NONE` | The permission takes no value. |
| `LUS_CAP_PATH` | Canonical file system path globs. |
| `LUS_CAP_HOST` | A host with an optional port and path glob, as in `host:port/path`. |
| `LUS_CAP_PATTERN` | A glob over an opaque string. |
| `LUS_CAP_CUSTOM` | The extension supplies a function that compares the two values. |

The following extension declares the permission `store` with the subpermissions `read` and `write`. Its `store.get` function checks `store:read` for the key it reads.

```c
static const char *const store_subs[] = {"read", "write", NULL};

/* store.get(key) requires store:read for the key. */
static int store_get(lus_State *L) {
  const char *key = lus_tostring(L, 1, NULL);
  if (key == NULL)
    return lus_errorf(L, "bad argument #1 to 'get' (string expected)");
  if (lus_require(L, "store:read", key) != LUS_OK)
    return lus_error(L);
  return lus_pushfstring(L, "value of %s", key) == LUS_OK ? 1 : lus_error(L);
}

static void open_store(lus_State *L) {
  lus_Capability cap = {0};
  cap.name = "store";
  cap.subcapabilities = store_subs;
  cap.kind = LUS_CAP_PATTERN;
  lus_defcapability(L, &cap);
  lus_newtable(L, 0, 1);
  lus_pushcfunction(L, store_get);
  lus_setfield(L, -2, "get");
  lus_setglobal(L, "store");
}
```

After `lus_grant(L, "store:read=users/*")`, the call `store.get("users/ada")` succeeds. The call `store.get("secrets/key")` raises `permission "store:read" denied for 'secrets/key'`.
