Lus 2.0 adds two pieces of loop syntax. The `continue` statement starts the next iteration of the innermost loop, and the `range` function writes a numeric loop in the same `for ... in` form as every other loop.

## Continue

The `continue` statement skips the rest of the current iteration of the innermost enclosing loop. It works in numeric and generic `for` loops, in `while` loops, and in `repeat` loops.

```lus
global print

for i = 1, 10 do
    if i % 3 == 0 then continue end
    print(i)
end
```

In a `for` loop, `continue` advances to the next value. In a `while` loop it evaluates the condition again. In a `repeat` loop it jumps to the `until` condition, which decides whether the loop runs again.

```lus
global print

local attempts = 0
repeat
    attempts = attempts + 1
    if attempts % 2 == 1 then continue end
    print(`even attempt $attempts`)
until attempts >= 6
```

The condition of a `repeat` loop can read the locals of the loop body. A `continue` that would skip the declaration of such a local is a compile error, because the condition would then read a variable that was never initialized. The following loop is rejected with `<continue> at line 4 jumps into the scope of 'done'`:

```lus
local i = 0
repeat
    i = i + 1
    if i < 3 then continue end
    local done = true
until done
```

Declaring the local before the `continue` fixes it. A `continue` outside every loop is also a compile error, and so is a `continue` inside a function nested in a loop, since the function body is not part of the loop.

`continue` is a reserved word. A program that used `continue` as a variable name or as a `goto` label renames it.

## Range

The global function `range` produces the numbers of an arithmetic sequence. `range(a, b)` counts from `a` to `b` inclusive, `range(a, b, step)` advances by `step`, and `range(n)` counts from 1 to `n`. A negative step counts down, and a step of zero raises an error.

```lus
global print, range

for i in range(1, 5) do print(i) end        --> 1 2 3 4 5
for i in range(10, 1, -3) do print(i) end   --> 10 7 4 1
for i in range(3) do print(i) end           --> 1 2 3
for x in range(0, 1, 0.25) do print(x) end  --> 0.0 0.25 0.5 0.75 1.0
```

When a `for` loop calls `range` directly, the compiler emits exactly the numeric loop that `for i = a, b, step` produces, so the two forms run at the same speed and follow the same rules: the bounds and the step are evaluated once, the loop variable is local to the body, and an integer loop stays in integers. Anywhere else `range` is an ordinary function that returns an iterator, a state, and a control value, so it can be stored, passed around, and consumed by any generic `for`.

```lus
global print, range

local iter, state, control = range(2, 10, 2)
for i in iter, state, control do print(i) end  --> 2 4 6 8 10
```

The numeric `for` statement keeps working unchanged. `range` gives the numeric loop the same shape as the loops over tables and other iterators, which reads uniformly in code that mixes them.

## Motivation

### Continue

Skipping the rest of an iteration is one of the most common control flow needs, and `continue` states that intent in one word. The body of the loop stays flat, the early exits sit next to the conditions that cause them, and [`lus check`](/manual/acquis-39) recognizes the code after a `continue` as unreachable.

### Range

`range` makes the numeric loop a special case of the generic loop in the source, while the compiler keeps it a numeric loop in the bytecode. A direct call costs nothing at run time, and the same function remains a first-class iterator everywhere else.
