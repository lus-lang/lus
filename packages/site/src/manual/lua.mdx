Lus is derived from Lua 5.5. A Lua program needs a few changes before it runs in Lus, which [Porting a Lua program](#porting-a-lua-program) lists. Lus also adds syntax and libraries that replace several common Lua idioms.

## How the languages relate

Lus keeps the core of Lua: tables, metatables, functions as values, multiple results, coroutines, 1-based indexing, and a small grammar. Most Lua code is valid Lus.

The two languages have different purposes. Lua is an extension language. It runs inside a host program written in C. The host supplies most of what a script uses: file operations beyond the basic ones, networking, threads, and the rules for what a script may do. This keeps Lua small enough for game engines, routers, and editors.

Lus is a language for complete programs. The `lus` executable runs a script without a host. It contains the libraries and tools that such a program needs, such as JSON, file operations, networking, a database, a test runner, and a formatter. A host program can still embed Lus with the C interface in [`lus.h`](/manual/embedding).

This difference of purpose explains most of the differences between the two languages. A program that runs without a host needs a larger standard library, a way to limit its own access to the system, and a string type that is safe to treat as text.

## Porting a Lua program

A Lua 5.5 program may need six changes before it runs in Lus. The six changes are to strings that hold bytes, calls to removed functions, global names, names that are now reserved words, permissions, and modules written in C.

### What runs unchanged

The following parts of Lua 5.5 behave in Lus as they do in Lua. Library functions that access the system also need [permissions](#permissions).

- The syntax of Lua 5.5, including `goto`, integer division, the bitwise operators, `global` declarations, and the `<const>` and `<close>` attributes.
- Integers and floats, with the same arithmetic, conversions, and wraparound on integer overflow.
- Tables, metatables, and every metamethod, including `__index`, `__close`, `__gc`, and `__pairs`.
- Coroutines, `error`, `assert`, `require`, `load`, and `_ENV` environments.
- The `table`, `math`, `os`, `coroutine`, `debug`, and `package` libraries, except the [removed functions](#removed-functions).
- The `string`, `utf8`, and `io` libraries, except that positions count characters and binary data is a vector. [Strings and bytes](#strings-and-bytes) lists these differences.
- String patterns, with the same items and the same functions. A pattern item matches a whole character. The classes such as `%a` and `%w` match ASCII characters only, as in Lua, so `%a` does not match `é`.
- Named variable arguments. `function f(...args)` collects the extra arguments into the table `args`. `args.n` is their count.

The `lus` command runs a file with any extension, so `lus app.lua` works. `require` looks for `name.lus` and `name/init.lus` first, then for `name.lua` and `name/init.lua`. A project can therefore move to Lus one file at a time.

### `lus check`

`lus check` reads source files without running them. It reports compile errors, likely mistakes, and Lua idioms that have a direct Lus form. Its report on a Lua program lists much of what needs to change. The following Lua file prints the server host from a configuration file.

```lua
local function load_config(path)
    local ok, result = pcall(dofile, path)
    if not ok then
        return nil, result
    end
    return result
end

local config = load_config("config.lua")
local host = config and config.server and config.server.host
if host then
    print(host)
end
```

`lus check config_host.lua` prints one line for each finding, with the position, the message, and a code in brackets.

```text
config_host.lua:2:24: warning: 'pcall' no longer exists, use a 'catch' expression instead [deprecated-pcall]
config_host.lua:10:1: warning: local declaration can be moved to the if condition (use if-assignment) [use-if-assign]
config_host.lua:10:14: warning: and-chain can use optional chaining: x?.y?.z [use-optional-chain]
```

The first warning must be fixed, because the call to `pcall` raises an error in Lus. The other two warnings are suggestions. The code that they refer to runs as written. A file that uses a new reserved word as a name has a syntax error, which is then the only finding that `lus check` reports. `lus check` reports neither the other removed functions nor missing permissions. Those raise errors when the program runs. Each error names the missing function or the missing permission. [Developer tools](/manual/tools#checking) describes every diagnostic.

### Strings and bytes

A Lua string is a sequence of bytes with no encoding. The same type holds UTF-8 text, text in other encodings, and binary data. `#s` is the number of bytes. This keeps the string library small. A host can also pass any buffer to Lua and get it back unchanged. Text is harder to handle, because a byte position can be in the middle of a character.

```lua
local s = "héllo"
print(#s)                               -- 6
print(s:sub(1, 2))                      -- "h" and the first byte of "é"
print(s:sub(1, utf8.offset(s, 3) - 1))  -- "hé"
```

A Lus string is text. Every string operation counts characters. A _character_ is one Unicode code point. Bytes have a separate type, the _vector_. A vector is a resizable buffer of bytes whose offsets start at 0.

```lus
local s = "héllo"
print(#s, s:sub(1, 2), s:upper())       --> 5  hé  HéLLO
print(s:byte(2), string.char(233))      --> 233  é

local bytes = vector.fromstring(s)
print(#bytes, vector.get(bytes, 1), vector.get(bytes, 2))   --> 6  195  169
print(vector.tostring(bytes) == s)      --> true
```

Code can measure, cut, and print any Lus string without first checking that it is valid text. Converting between bytes and text takes an explicit call, such as `vector.fromstring`. Lua code that uses strings as text needs no change. Its calls to `utf8.offset` are no longer necessary. Lua code that uses strings as byte arrays must account for the following differences.

- `#s`, `string.sub`, `string.find`, and the other string functions take and return character positions. The width in a `string.format` specifier such as `%5s` also counts characters.
- `utf8.offset`, `utf8.codepoint`, and `utf8.codes` take and return character positions too. `utf8.offset("héllo", 3)` is 3, so Lua code that combined them with `string.sub` keeps working.
- `string.byte` returns code points. `string.char` builds a string from code points. `vector.get` and `vector.set` read and write single bytes.
- A string literal must be valid text. A literal such as `"\xFF"` is a compile error. The error message recommends a vector.
- `string.pack` and `string.dump` return vectors. `string.unpack` and `load` accept them.
- A file opened in binary mode, with `"b"` in its mode string, reads vectors. A file opened in text mode reads strings. Reading bytes that are not valid text from such a file raises an error.
- Sockets and `network.fetch` return vectors.

The following example writes a binary record of two integers to a file and reads it back as a vector.

```lus
pledge("fs")

local packed = string.pack("<I2I2", 513, 7)
print(type(packed), #packed, vector.get(packed, 0), vector.get(packed, 1))   --> vector  4  1  2
print(string.unpack("<I2I2", packed))   --> 513  7  5

local path = os.tmpname()
io.open(path, "wb"):write(packed):close()
local file <close> = io.open(path, "rb")
local data = file:read("a")
print(type(data), #data)                --> vector  4
fs.remove(path)
```

[Text and bytes](/manual/text) describes strings, vectors, and the conversions between them in full.

### Removed functions

Lus removes four Lua functions and two environment variables. Each has a replacement. A call to a removed function raises the error `attempt to call a nil value`, with the name of the function.

| Lua | Lus |
| --- | --- |
| `pcall(f, ...)` | `catch f(...)`, described under [Errors with `catch`](#errors-with-catch) |
| `xpcall(f, handler, ...)` | `catch[handler] f(...)` |
| `os.remove(path)` | [`fs.remove(path)`](/manual/api#fs.remove) |
| `os.rename(old, new)` | [`fs.move(old, new)`](/manual/api#fs.move) |
| The `LUA_PATH` environment variable | The `LUS_PATH` environment variable |
| The `LUA_INIT` environment variable | The `-e` and `-l` options of `lus` |

`os.remove` and `os.rename` return `nil` and a message on failure. `fs.remove` and `fs.move` raise an error. Code that tested the result of the Lua function uses `catch` in Lus. In the following example, the second call to `fs.remove` fails because the file is already removed.

```lus
pledge("fs")

local path = os.tmpname()
fs.move(path, path .. ".bak")
fs.remove(path .. ".bak")
print((catch fs.remove(path .. ".bak")))   --> false
```

### New global names

Lus adds the following globals: `bigint`, `decimal`, `flags`, `fromcsv`, `fromjson`, `fs`, `network`, `pledge`, `query`, `time`, `tocsv`, `tojson`, `vector`, and `worker`. A Lua program that assigns to a global with one of these names replaces the Lus value for the whole program. The program then cannot use that Lus library. A local variable with one of these names shadows the global, as in Lua. The exception is `flags`, which is readonly. Assigning to the global `flags` is a compile error.

### Reserved words

Lus adds five reserved words to those of Lua 5.5: `catch`, `continue`, `enum`, `from`, and `provide`. A Lua program that uses one of them as the name of a variable, a field written after a dot, or a label must rename it. The most common case is a label named `continue` at the end of a loop body.

```lua
for _, line in ipairs(lines) do
    if line == "" then goto continue end
    process(line)
    ::continue::
end
```

Lus rejects this file with the syntax error `<name> expected near 'continue'`. To fix it, delete the label and replace each `goto continue` with the [`continue`](#continue) statement. A field whose name is a reserved word is read and written with brackets, as in `t["from"]`.

### Permissions

A Lua script can open any file and run any command that the operating system allows its process. To limit a script, the host program chooses which libraries the script receives. A Lus program runs without a host, so Lus has _permissions_. A script starts with no access to files, the network, other processes, or environment variables. It acquires each kind of access by calling the function `pledge`. Most ported scripts therefore need one added line, a call to `pledge`.

A call that needs a permission that the script does not hold raises an error. The error message names the permission. In the following script, `io.open` fails until the script pledges `fs:read`.

```lus nocheck
print(catch io.open("notes.txt"))
--> false  script.lus:1: permission "fs:read" denied for 'notes.txt'

pledge("fs:read")
local file = io.open("notes.txt")
```

The following table lists the permission that each Lua library function needs.

| Function | Permission |
| --- | --- |
| `io.open` and `io.lines` on a file that is read | `fs:read` |
| `io.open` for writing, `io.tmpfile`, `os.tmpname` | `fs:write` |
| `require` of a module file, `dofile`, `loadfile` | `fs:read` and `load` |
| `load` | `load` |
| `os.execute`, `io.popen` | `exec` |
| `os.getenv` | `env` |

A program that consists of several files needs `fs:read` and `load` for `require`. Without them, `require` skips the files that it may not read and reports that the module was not found. Such a program starts with the following pledge.

```lus nocheck
pledge("fs:read", "load")

local util = require("util")
```

`pledge` is an ordinary function, so a program may call it at any point. A pledge may limit a permission to certain paths or hosts, as in `pledge("fs:read=./data/*")`. After `pledge("seal")`, the program can acquire no more permissions. The `-P` option of `lus` also grants permissions, so an unmodified Lua script can run without a call to `pledge`. `-Pall` grants every permission.

```sh
lus -Pfs:read -Pload app.lua
lus -Pall app.lua
```

When the command line grants any permission, the script may pledge only what the command line granted. [Permissions](/manual/permissions) is the complete reference for permission names, values, rejection, sealing, and the rules for coroutines and workers.

### C modules

In Lua, `require` reads `package.cpath` to find modules written in C. `package.cpath` is a string of file name templates, such as `./?.so`. `require` replaces the `?` in each template with the module name and loads the first file that exists. `package.loadlib` loads a C library from a path that the program gives. Lus loads no native libraries at run time. In Lus, `package.cpath` is the empty string. `package.loadlib` returns `nil` and a message that says native libraries are unavailable.

The Lus standard library has a counterpart for most C modules that Lua programs depend on. [The standard library](#the-standard-library) lists them. Native code without a counterpart must be part of a host program that embeds Lus. The host registers its C functions with the functions of `lus.h`, as [Embedding](/manual/embedding) describes. `lus.h` differs from the C API of Lua. Its functions have the prefix `lus_` and return a status code on failure. A C module written for Lua must therefore be ported to `lus.h`.

## Lus forms for Lua idioms

Some Lua idioms still work in Lus but are no longer the best way to write the code, because Lus has syntax or a library function for the same job. The only Lua forms that stop working are those listed under [Porting a Lua program](#porting-a-lua-program). A ported program can therefore adopt the Lus forms one at a time.

### Errors with `catch`

Lua catches [errors](/manual/guide#errors) with `pcall`. `pcall` calls a function. It returns `true` and the results of the function, or `false` and the error object. `xpcall` also takes a handler function. The handler receives the error object. Its result replaces the error object that `xpcall` returns. Both are ordinary functions, as in the C API of Lua, so Lua needs no syntax for catching errors. Both protect one function call. To protect an expression, a Lua program wraps it in a function.

```lua
local ok, port = pcall(function()
    return json.decode(text).server.port
end)

local ok, err = xpcall(load_settings, function(e)
    return { cause = e, operation = "load settings" }
end, "app.toml")
```

The wrapped code is in a different function. A `return` inside the wrapper returns from the wrapper only. The `...` of the enclosing function is unavailable inside it. Code can therefore change meaning when it is moved into a `pcall`. In a call to `xpcall`, the handler is written between the function and its arguments.

In Lus, `catch` is a keyword that is followed by an expression. `catch` evaluates the expression. It returns `true` and every result of the expression, or `false` and the error object.

```lus
local ok, port = catch fromjson('{"server": {"port": 8080}}').server.port
print(ok, port)      --> true  8080

local failed, err = catch fromjson('{"server": ').server.port
print(failed, err)   --> false  JSON parse error at position 12: unexpected end of input
```

A _catch handler_ is a function written in brackets after `catch`. The catch handler receives the error object. Its result replaces the error object that `catch` returns. It corresponds to the handler of `xpcall`.

```lus
local function describe(e)
    return { cause = e, operation = "load settings" }
end

local function load_settings(path)
    error(`cannot read $path`, 0)
end

local ok, err = catch[describe] load_settings("app.toml")
print(ok, err.operation, err.cause)   --> false  load settings  cannot read app.toml
```

A `catch` can also be a statement. It evaluates the expression and discards the results or the error. This is useful for cleanup whose failure does not matter.

```lus
pledge("fs:write")

catch fs.remove("cache.tmp")   -- the file may not exist
print("done")                  --> done
```

The protected expression is part of the enclosing function, so it can use the local variables and the `...` of that function. `error`, `assert`, and error objects of any type work as in Lua. [Do expressions](#do-expressions) shows how `catch` protects several statements.

### Optional chaining

To read a field of a value that may be `nil`, a Lua program tests each step with `and`.

```lua
local host = config and config.server and config.server.host or "localhost"
local name = find_user(id) and find_user(id).name
```

The expression repeats every prefix, so it grows with each level of nesting. A prefix that is a call runs once for each time it is written. The second line therefore calls `find_user` twice, unless the program first stores the result in a local variable.

In Lus, a `?` after a value makes the next step optional. This syntax is [optional chaining](/manual/guide#optional-chaining). If the value before `?` is `nil` or `false`, that value is the result of the whole chain. Lus skips the rest of the chain. Otherwise the chain continues. Each prefix is written once and evaluated once.

```lus
local calls = 0
local function find_user(id)
    calls = calls + 1
    if id == 1 then
        return { name = "Ada" }
    end
end

print(find_user(1)?.name, find_user(2)?.name, calls)   --> Ada  nil  2

local config = { server = {} }
print(config?.server?.host or "localhost")             --> localhost
```

The `?` suffix also works before a method call, as in `file?:read("l")`. It works before a function call too, as in `on_done?(result)`. The following example calls a callback only when one is set.

```lus
local on_done = nil
local result = on_done?("finished")
print(result)   --> nil
```

The `?` suffix gives the same result as the `and` idiom in every case. In particular, `false` stops the chain and is its result. An expression rewritten from one form to the other therefore keeps its value.

### String interpolation

A Lua program builds a message with the `..` operator or with `string.format`. `string.format` also controls how numbers are formatted.

```lua
local msg = "user " .. name .. " has " .. count .. " items (" .. tostring(active) .. ")"
local msg = string.format("user %s has %d items (%s)", name, count, tostring(active))
```

The `..` operator raises an error for `nil` and for booleans, so each such value needs a call to `tostring`. If a value is unexpectedly `nil`, the line that was written to report the problem raises an error itself. With `string.format`, the values are written after the format string, away from the specifiers that mark their places in the text. The specifiers must match the arguments in number and order.

In a Lus [string written between backticks](/manual/guide#strings), `$name` inserts the value of a variable. `$(expression)` inserts the result of an expression. Lus converts every inserted value as `tostring` does, including `nil` and booleans.

```lus
local name, count, active = "ada", 3, true

print(`user $name has $count items ($active)`)    --> user ada has 3 items (true)
print(`next: $(count + 1), missing: $(nil)`)      --> next: 4, missing: nil
print(`total: $(string.format("%.2f", 19.5))`)    --> total: 19.50
```

Each value is written at the place where it appears in the text. `string.format` is still the way to control padding and precision, as the last line shows. `..` works as in Lua.

### Conditions that declare variables

A Lua program declares a variable before the `if` or `while` that tests it.

```lua
local value = env[name]
if value then
    return value, "env"
end
local fallback = defaults[name]
if fallback then
    return fallback, "default"
end

local line = file:read()
while line do
    process(line)
    line = file:read()
end
```

Each local variable stays in scope after its test, until the end of the enclosing block. Each fallback needs another variable name and another `if`. The `while` loop contains the call to `file:read` twice, once before the loop and once at the end of its body.

In Lus, the [condition](/manual/guide#conditions-that-declare-variables) of an `if`, an `elseif`, or a `while` may declare a variable with `name = expression`. Lus assigns the value and tests it. The variable is in scope until the `end` of the statement. A sequence of fallbacks is then one `if` statement with an `elseif` for each fallback.

```lus
local env = { PORT = "8080" }
local defaults = { HOST = "localhost" }

local function lookup(name)
    if value = env[name] then
        return value, "env"
    elseif value = defaults[name] then
        return value, "default"
    end
    return nil, "unset"
end

print(lookup("PORT"))   --> 8080  env
print(lookup("HOST"))   --> localhost  default
print(lookup("USER"))   --> nil  unset
```

A `while` condition of this form contains the call once. Lus evaluates it before each iteration.

```lus
local queue = { "first", "second" }
while job = table.remove(queue, 1) do
    print(job)   --> first, then second
end
```

### Destructuring with `from`

A Lua program copies fields into local variables by assigning each one.

```lua
local cfg = load_config()
local host = cfg.host
local port = cfg.port
local timeout = cfg.timeout
local insert, concat = table.insert, table.concat
```

Each name is written twice, once as the variable and once as the field. When the table comes from a call, the program stores it in a variable first so that the call runs once.

In Lus, [`local a, b from t`](/manual/guide#destructuring-with-from) declares the variables `a` and `b` with the values of `t.a` and `t.b`. Lus evaluates the expression after `from` once, whatever the number of names.

```lus
local function load_config()
    return { host = "localhost", port = 8080, timeout = 30 }
end

local host, port, timeout from load_config()
print(host, port, timeout)    --> localhost  8080  30

local insert, concat from table
local parts = {}
insert(parts, "a")
insert(parts, "b")
print(concat(parts, "+"))     --> a+b
```

`from` also works in an assignment to existing variables, in a `global` declaration, and in a condition. With a call to `require` after `from`, one line imports several functions of a module, as in `local encode, decode from require("codec")`.

### `continue`

Lua has no `continue` statement. One difficulty is that a `continue` inside `repeat ... until` could skip the declaration of a local variable that the `until` condition reads. Since Lua 5.2, a program skips the rest of an iteration with `goto` and a label at the end of the loop body.

```lua
for _, line in ipairs(lines) do
    if line == "" then goto continue end
    if line:sub(1, 1) == "#" then goto continue end
    process(line)
    ::continue::
end
```

Every loop that skips iterations needs a label at the end of its body. A label must not have the same name as another visible label. A loop nested inside another loop that also skips iterations therefore needs a different label name.

In Lus, the [`continue`](/manual/guide#break-and-continue) statement skips the rest of the current iteration of the innermost enclosing loop. It works in every kind of loop.

```lus
local lines = { "alpha", "", "# note", "beta" }

for _, line in ipairs(lines) do
    if line == "" then continue end
    if line:sub(1, 1) == "#" then continue end
    print(line)   --> alpha, then beta
end
```

In a `repeat` loop, a `continue` that would skip such a declaration is a compile error. Lus rejects the following loop for that reason.

```lus nocheck
local i = 0
repeat
    i = i + 1
    if i < 3 then continue end   -- compile error: this skips the declaration of 'done'
    local done = true
until done
```

### Enums

A Lua program represents a fixed set of choices with strings or with a table of numbered constants.

```lua
local state = "suspended"
if state == "suspnded" then resume() end

local Status = { ACTIVE = 1, SUSPENDED = 2, CLOSED = 3 }
if row.flags == Status.SUSPENDED then resume() end
```

A misspelled string is still a valid string. The first test is therefore always false, yet Lua reports no error. A numbered constant is equal to any number with the same value, such as a count or an identifier.

A Lus [`enum`](/manual/guide#enums) declares _members_. A member has the type `enum` and is equal only to itself. Members compare with `<` in the order of their declaration. A member can be a table key. `tonumber` returns the position of a member in its declaration.

```lus
local Status = enum active, suspended, closed end

local labels = {
    [Status.active] = "Active",
    [Status.suspended] = "Suspended",
    [Status.closed] = "Closed",
}

local current = Status.suspended
print(type(current), labels[current])              --> enum  Suspended
print(current == "suspended", current == 2)        --> false  false
print(current < Status.closed, tonumber(current))  --> true  2
```

A member is never equal to a string or a number, so data that contains the same name or position cannot be mistaken for it. `tostring` converts a member to its type and an address, such as `enum: 0x0000010143c030`. A program therefore keeps display text in a table with members as keys, such as `labels`.

### Exact numbers

A Lua number is a 64-bit integer or a 64-bit float. Both fit in a machine register, which keeps arithmetic fast. Integer arithmetic wraps around on overflow. A float cannot hold most decimal fractions exactly.

```lua
print(math.maxinteger + 1)     -- -9223372036854775808
print(0.1 + 0.2 == 0.3)        -- false

local total = 0
for _ = 1, 10 do total = total + 0.10 end
print(total == 1.0)            -- false
```

A Lua program that handles money therefore stores every amount as an integer number of cents. A Lua program that handles identifiers wider than 64 bits stores them as strings.

Lus keeps integers and floats with the same behavior and adds two exact subtypes of [`number`](/manual/guide#numbers). A _bigint_, written with the suffix `n`, is an integer of any size. A _decimal_, written with the suffix `d`, is a number that keeps its exact fractional part.

```lus
print(math.maxinteger + 1)                 --> -9223372036854775808
print(math.maxinteger + 1n, 2n ^ 100)      --> 9223372036854775808  1267650600228229401496703205376

local total = 0d
for _ = 1, 10 do
    total = total + 0.10d
end
print(total, total == 1)                   --> 1.00  true

local price = 19.99d
print(price * 3, price * 0.0825d)          --> 59.97  1.649175
print(math.type(2n), math.type(price))     --> bigint  decimal
```

The [arithmetic](/manual/guide#arithmetic) and comparison operators accept both subtypes. Two numbers with the same mathematical value are equal, whatever their subtypes. Arithmetic between a decimal and a float raises an error, because the float would make the result inexact. The functions `decimal` and `bigint` convert a number or a string to these subtypes.

```lus
print(3n == 3, 0.5d == 0.5)                --> true  true
print((catch 19.99d * 1.5))                --> false
print(19.99d * decimal("1.5"))             --> 29.985
```

### Slices

A Lua program copies part of a sequence with `table.unpack` inside a constructor or with `table.move`. It copies part of a string with `string.sub`.

```lua
local middle = { table.unpack(list, 2, 4) }
local tail = table.move(list, 3, #list, 1, {})
local word = text:sub(2, 4)
```

`table.unpack` places every element on the stack, so a long range fails with the error `too many results to unpack`. `table.move` needs five arguments for one copy.

In Lus, the [slice](/manual/guide#slices) `t[i, j]` copies the positions from `i` to `j` of a table, a string, or a vector. Either bound may be left out.

```lus
local list = { 10, 20, 30, 40, 50 }
print(table.concat(list[2, 4], " "))   --> 20 30 40
print(table.concat(list[3, ], " "))    --> 30 40 50
print(table.concat(list[, 2], " "))    --> 10 20
print(("héllo")[2, 4])                 --> éll
```

A string slice counts characters. A vector slice counts bytes.

### `table.clone`

The Lua standard library has no function that copies a table. Most Lua projects contain a version of the following function.

```lua
local function deepcopy(t, seen)
    if type(t) ~= "table" then return t end
    seen = seen or {}
    if seen[t] then return seen[t] end
    local copy = {}
    seen[t] = copy
    for k, v in pairs(t) do
        copy[deepcopy(k, seen)] = deepcopy(v, seen)
    end
    return setmetatable(copy, getmetatable(t))
end
```

The versions differ in whether they copy keys and metatables. A version without the `seen` table recurses without end on a table that contains itself.

[`table.clone(t)`](/manual/api#table.clone) makes a shallow copy. `table.clone(t, true)` makes a deep copy. A deep copy copies each table once, even when the original refers to that table several times or the table contains itself.

```lus
local defaults = { name = "app", ports = { 80, 443 } }
defaults.self = defaults

local shallow = table.clone(defaults)
local deep = table.clone(defaults, true)
deep.ports[1] = 8080

print(shallow.ports == defaults.ports, defaults.ports[1])   --> true  80
print(deep.self == deep, deep.ports[1])                     --> true  8080
```

Both copies have the metatable of the original.

### Do expressions

When a value takes several statements to compute, a Lua program can write the statements in a function and call that function immediately.

```lua
local port = (function()
    for _, key in ipairs({ "port", "http_port", "PORT" }) do
        local n = tonumber(config[key])
        if n then return n end
    end
    return 8080
end)()
```

This idiom creates a function each time the line runs. A `return` inside the function returns from that function only, so the code cannot return from the enclosing function. The code also cannot use `break` on an enclosing loop or the `...` of the enclosing function. Another way is to declare the variable first and assign it inside the loop. The variable is then `nil` when no assignment runs, unless the program assigns a default after the loop.

A Lus [_do expression_](/manual/guide#do-expressions) is a `do ... end` block that is used as a value. The `provide` statement ends the block. Its operands are the values of the do expression. The block is part of the enclosing function, so Lus creates no function for it. Its local variables go out of scope at its `end`.

```lus
local config = { http_port = "8081" }

local port = do
    for _, key in ipairs({ "port", "http_port", "PORT" }) do
        if n = tonumber(config[key]) then
            provide n
        end
    end
    provide 8080
end
print(port)   --> 8081
```

The declaration of `port` contains the whole computation of its value. The variables `key` and `n` are out of scope after the block.

`catch` followed by a do expression protects several statements. This form replaces the Lua idiom `pcall(function() ... end)`. The following function reads a host and a port from a JSON text. Parsing the text and validating the port can both raise an error, so the function puts both steps in one do expression after `catch`.

```lus
local function parse_endpoint(text)
    return catch do
        local data = fromjson(text)
        local port = math.tointeger(data.port)
        if not port then
            error("port must be an integer", 0)
        end
        provide data.host or "localhost", port
    end
end

print(parse_endpoint('{"port": 8080}'))      --> true  localhost  8080
print(parse_endpoint('{"port": "http"}'))    --> false  port must be an integer
print(parse_endpoint('{"port": '))           --> false  JSON parse error at position 10: unexpected end of input
```

As in any block, a `return` inside a do expression returns from the enclosing function. A `break` or `continue` applies to the enclosing loop.

### Runtime attributes

To wrap a function, for example to log its calls or to cache its results, a Lua program defines the function and then replaces it with the wrapped version.

```lua
local function logged(name, fn)
    return function(...)
        print("call " .. name)
        return fn(...)
    end
end

local function area(w, h)
    return w * h
end
area = logged("area", area)
```

The wrapping is a separate statement after the function, where a reader may miss it. That statement contains the name of the function three times. A Lua program that checks every value assigned to a variable has a similar problem. It repeats the check at every assignment, or it replaces the variable with a table whose `__newindex` metamethod checks each value.

Lua 5.4 introduced the attributes `<const>` and `<close>`. In Lus, a program can define its own attributes. A [_runtime attribute_](/manual/guide#runtime-attributes) is a function written in angle brackets after the name of a local variable in its declaration. Lus calls the attribute at the declaration and at every later assignment in the function that declares the variable. The attribute receives the name of the variable and the value being assigned. Lus stores the value that the attribute returns. An attribute can therefore wrap a function where the function is declared.

```lus
local function logged(name, fn)
    return function(...)
        print(`call $name`)
        return fn(...)
    end
end

local area <logged> = function(w, h)
    return w * h
end

print(area(3, 4))   --> call area, then 12
```

The declaration names the wrapper before the body of the function. The wrapper receives the name `area` from Lus, so the program writes the name once.

An attribute can also check or convert every value that is assigned to a variable. The expression in the angle brackets may be any expression that evaluates to a function. It may be a call that returns the attribute. The arguments of the call configure it. When the attribute raises an error, the variable keeps its previous value. The following attribute rejects values below a minimum.

```lus
local function at_least(min)
    return function(name, value)
        if value < min then
            error(`$name must be at least $min, got $value`, 0)
        end
        return value
    end
end

local workers <at_least(1)> = 4
print(catch do workers = 0 end)   --> false  workers must be at least 1, got 0
print(workers)                    --> 4
```

The declaration states the check once. Lus applies it to every assignment to the variable in that function. An assignment in a nested function stores the value without calling the attribute. A variable whose values must always be checked must therefore be assigned only in the function that declares it.

### Local groups

A Lua program can keep a few related values in a table or in separate local variables. A table keeps the values together under one name. It costs an allocation and a table lookup for each access. Separate local variables have neither cost, but only their names show that they belong together.

```lua
local lo = { x = math.huge, y = math.huge }      -- one table
local hi_x, hi_y = -math.huge, -math.huge        -- or separate locals
```

The cost of the table matters in a function that runs often, because each call allocates a table that the garbage collector must later free.

A Lus [_local group_](/manual/guide#local-groups) is a set of local variables that are declared together under one name with the attribute `<group>`. Each field of a group is a local variable, so a group allocates no table. A field is read and written as `name.field`. Assigning a table constructor to the group assigns the fields that the constructor names. The other fields keep their values. The following example computes the bounding box of a list of points.

```lus
local points = { { x = 3, y = 8 }, { x = -2, y = 5 }, { x = 7, y = -1 } }

local lo <group> = { x = math.huge, y = math.huge }
local hi <group> = { x = -math.huge, y = -math.huge }

for _, p in ipairs(points) do
    lo = { x = math.min(lo.x, p.x), y = math.min(lo.y, p.y) }
    hi = { x = math.max(hi.x, p.x), y = math.max(hi.y, p.y) }
end
print(lo.x, lo.y, hi.x, hi.y)   --> -2  -1  7  8

hi = { y = 100 }
print(hi.x, hi.y)               --> 7  100
```

A group is a set of variables, so it cannot be passed to a function, returned, or stored in a table. The declaration fixes its set of fields. A table is still the right choice for data that is passed to another function or returned.

### Build flags

A Lua program enables optional behavior, such as debug output, with a global variable or an environment variable that it tests at run time.

```lua
local DEBUG = os.getenv("APP_DEBUG") ~= nil
if DEBUG then print("cache size", #cache) end
```

The test runs every time the line is reached. The optional code is part of the compiled program even when it can never run.

A [_flag_](/manual/guide#build-flags) is a field of the readonly global table `flags`. The `-F` option of `lus` sets a flag. `lus -Fverbose app.lus` sets `flags.verbose` to `true`. `-Flevel=3` sets `flags.level` to the number 3. A flag that was not set is `nil`. When the condition of an `if` is exactly `flags.name` or `not flags.name`, Lus evaluates it at compile time and omits the branch that cannot run from the compiled code.

```lus
local cache = { 1, 2, 3 }

if flags.verbose then
    print("cache size", #cache)   -- compiled only with -Fverbose
end
print(flags.verbose)              --> nil
```

A disabled branch therefore takes no time and no space at run time. `lus build` with `-F` stores the flags in a standalone executable, so one source tree can produce both a debug build and a release build.

### Queries

A Lua program filters, reshapes, and orders a list of records with a loop and `table.sort`.

```lua
local big = {}
for _, o in ipairs(orders) do
    if o.total >= 100 then
        big[#big + 1] = { customer = o.customer, total = o.total }
    end
end
table.sort(big, function(a, b) return a.total > b.total end)
```

The operation is divided among a loop, a condition, a constructor, and a comparison function. For a database table, the same operation is written again as an SQL string with its own parameters.

A Lus [_query_](/manual/guide#queries) is one expression that starts with `@`. It contains the source, the filter, the fields to keep, and the order. The function `query` runs a query and returns an iterator over the rows of the result.

```lus
local orders = {
    { customer = "Ada", total = 120 },
    { customer = "Linus", total = 40 },
    { customer = "Grace", total = 300 },
}

local big = @orders as o where o.total >= 100 select o.customer, o.total order by o.total desc

for row in query(big) do
    print(row.customer, row.total)   --> Grace  300, then Ada  120
end
```

The same query syntax works on a table of a [SQLite](/manual/sqlite) database. SQLite then evaluates the filter.

## The standard library

The standard library of Lua is small by design. An embedded interpreter should add little to the size of its host and depend on little of the platform. A Lua program that reads JSON or opens a socket installs a module. A module written in C must be compiled for every platform where the program runs.

A Lus program runs without a host, so the `lus` executable contains [libraries](/manual/guide#the-standard-library) for JSON, sockets, and other common tasks. The following table lists common tasks, a module that Lua programs often use for each task, and the Lus counterpart.

| Task | Common Lua module | Lus |
| --- | --- | --- |
| JSON | dkjson, lua-cjson | [`fromjson`](/manual/api#fromjson), [`tojson`](/manual/api#tojson) |
| CSV | A hand-written parser | [`fromcsv`](/manual/api#fromcsv), [`tocsv`](/manual/api#tocsv) |
| Directories and paths | LuaFileSystem | [`fs`](/manual/filesystem) |
| HTTP, TCP, and UDP | LuaSocket | [`network`](/manual/network) |
| SQLite | lsqlite3 | [`io.sqlite`](/manual/sqlite) |
| Time zones and calendar arithmetic | `os.date` with offsets computed by hand | [`time`](/manual/time) |
| Compression | lua-zlib | [`vector.archive`](/manual/text#compression) |
| Character sets | lua-iconv | [`string.transcode`](/manual/text#transcoding) |
| Splitting and trimming strings | Helpers copied between projects | [`string.split`](/manual/api#string.split), [`string.trim`](/manual/api#string.trim) |

The following example decodes JSON and CSV text. When the second argument of `fromcsv` is `true`, the first row gives the column names. A CSV parser written with `gmatch` usually drops empty fields and splits quoted fields that contain a comma. `fromcsv` follows RFC 4180, so it handles both cases. `string.split` keeps empty fields.

```lus
local data = fromjson('{"name": "Ada", "langs": ["lus", "lua"]}')
print(data.name, #data.langs)                  --> Ada  2
print(tojson({ ok = true }))                   --> {"ok":true}

local rows = fromcsv('name,city\nAda,"London, UK"\nLinus,', true)
print(rows[1].city, rows[2].city == "")        --> London, UK  true

print(#string.split("a,,b", ","), string.trim("  x  "))   --> 3  x
```

The `fs` library lists, creates, copies, moves, and removes files and directories. `fs.path` contains functions for path strings, such as `fs.path.join`. The following example creates a directory with two files, lists the files, and removes the directory.

```lus
pledge("fs")

local base = os.tmpname()
local dir = base .. ".d"
fs.createdirectory(dir)
io.open(fs.path.join(dir, "a.txt"), "w"):write("first"):close()
io.open(fs.path.join(dir, "b.txt"), "w"):write("second"):close()

local names = fs.list(dir, "*.txt")
table.sort(names)
print(table.concat(names, " "), (fs.type(dir)))   --> a.txt b.txt  directory

fs.remove(dir, true)
fs.remove(base)
```

`io.sqlite` opens a SQLite database in a file or in memory. An SQL statement receives its values as parameters. A query returns each row as a table. The following example stores two users in a database in memory and prints the names of the adults.

```lus
local db <close> = io.sqlite(":memory:")
db:exec("CREATE TABLE users (name TEXT, age INTEGER)")
db:run("INSERT INTO users VALUES (?, ?)", "Ada", 36)
db:run("INSERT INTO users VALUES (?, ?)", "Linus", 12)

for row in db:query("SELECT name FROM users WHERE age >= ?", 18) do
    print(row.name)   --> Ada
end
```

The `time` library has one type for a moment in time and another for a calendar date and time of day in a time zone. It includes the IANA time zone database. The following example prints a launch time in UTC and in New York, then the date 72 hours later.

```lus
local launch = time.instant(1782998100)
print(launch:iso())                                    --> 2026-07-02T13:15:00Z
print(launch:at(time.zone("America/New_York")):iso())  --> 2026-07-02T09:15:00-04:00
print((launch + time.hours(72)):format("%A %d %B"))    --> Sunday 05 July
```

`vector.archive` compresses and decompresses with gzip, deflate, Zstandard, Brotli, and LZ4. `string.transcode` converts text between character sets. Both return a vector when the result is bytes. The following example compresses a text with gzip and restores it. It then converts a string to UTF-16 and back.

```lus
local text = string.rep("hello world ", 100)
local packed = vector.archive.gzip.compress(text)
print(#packed < #text)                                                 --> true
print(vector.tostring(vector.archive.gzip.decompress(packed)) == text) --> true

local utf16 = string.transcode("hé", "utf-8", "utf-16le")
print(#utf16, string.transcode(utf16, "utf-16le", "utf-8"))            --> 4  hé
```

`network.fetch` makes an HTTP or HTTPS request and returns the status, the body as a vector, and the headers. The following program counts the items that a remote API returns.

```lus nocheck
pledge("network:http=api.example.com/*")

local status, body = network.fetch("https://api.example.com/v1/items")
if status == 200 then
    local items = fromjson(vector.tostring(body))
    print(#items)
end
```

These libraries make the `lus` executable larger than `lua`. A host that embeds Lus may leave the network, worker, SQLite, and compression libraries out of its build, as [Compiling Lus](/manual/compiling) describes.

## Concurrency

Lua coroutines are cooperative. A coroutine runs until it yields. The code that resumed it then continues and chooses which coroutine to resume next. The program or its host must therefore schedule the coroutines. Lus keeps [coroutines](/manual/guide#coroutines) unchanged. It adds a scheduler for coroutines that wait on sockets and adds workers for parallel computation.

### Detached coroutines

A program that serves many network connections spends most of its time waiting. It must wait for all the connections at once. A Lua program does this with an event library and registers a callback for each event.

```lua
local uv = require("luv")
local client = uv.new_tcp()
client:connect("127.0.0.1", 8080, function(err)
    client:write("GET / HTTP/1.1\r\n\r\n")
    client:read_start(function(err, chunk)
        -- every chunk of the response arrives here
    end)
end)
uv.run()
```

The code for one connection is divided among nested callbacks. An error raised in a callback does not reach a `pcall` around the code that started the request.

In Lus, [`coroutine.detach`](/manual/api#coroutine.detach) registers a coroutine with the Lus scheduler. Such a coroutine is a _detached coroutine_. A `receive`, `send`, `accept`, or `connect` in a detached coroutine suspends that coroutine only. Lus runs the other coroutines in the meantime and resumes the suspended one when its socket is ready. The code for one connection is therefore sequential, with ordinary loops, `catch`, and `<close>` variables. A socket call in the main chunk blocks as usual. Lus runs the detached coroutines while the main chunk waits. The following program runs an echo server and two clients in one thread. Each connection has its own detached coroutine.

```lus
pledge("network:tcp")

local server = network.tcp.bind("127.0.0.1", 0)
local _, port = server:getsockname()

local function echo(conn)
    local closing <close> = conn
    while true do
        local line = vector.tostring(conn:receive("*l"))
        if line == "" then
            break
        end
        conn:send(`echo: $line\n`)
    end
end

local acceptor = coroutine.detach(coroutine.create(function()
    while true do
        coroutine.detach(coroutine.create(echo), server:accept())
    end
end))

local a = network.tcp.connect("127.0.0.1", port)
local b = network.tcp.connect("127.0.0.1", port)
a:send("first\n")
b:send("second\n")
print(vector.tostring(b:receive("*l")))   --> echo: second
print(vector.tostring(a:receive("*l")))   --> echo: first

a:close()
b:close()
coroutine.close(acceptor)
server:close()
```

Both connections are open at the same time. The server answers `b` while the coroutine that serves `a` waits for its next line. The function `echo` is written as it would be for a single blocking connection. [`coroutine.resume`](/manual/api#coroutine.resume) on a detached coroutine waits until the coroutine ends. It then returns the results or the error of the coroutine, so a program calls it to collect the result of a task.

### Workers

Detached coroutines share one thread, so they do not speed up computation. In Lua, a C host does parallel work by running separate Lua states on separate threads.

A Lus _worker_ is a script that runs on another thread with its own state. [`worker.create`](/manual/api#worker.create) starts a worker and passes it arguments. A worker and its creator share no values. They exchange copies of values as messages, so data races cannot occur. In the following program, the script `primes.lus` counts the primes between its two arguments and sends the count with `worker.message`. Two workers count the two halves of a range in parallel.

```lus nocheck
pledge("fs:read", "load")

local low = worker.create("primes.lus", 1, 50000)
local high = worker.create("primes.lus", 50001, 100000)
print(worker.receive(low) + worker.receive(high))   --> 9592
```

[Workers](/manual/concurrency#workers) shows complete programs. The following table lists the right tool for each kind of problem.

| Problem | Tool |
| --- | --- |
| Many operations that wait on sockets, such as connections and timeouts | Detached coroutines |
| Computation that should use several processor cores | Workers |
| Several HTTP requests with `network.fetch` at once, since `fetch` blocks its thread | Workers |
| A sequence of values produced on demand, such as an iterator | Plain coroutines, as in Lua |

[Coroutines and workers](/manual/concurrency) describes both in full.

## Restricting loaded code

A Lua program limits the code that it loads, such as a plugin, with an environment table. `load` takes the table as its fourth argument. The loaded code reads and writes its global variables in that table.

```lua
local env = { print = print, tonumber = tonumber, io = io }
local chunk = load(source, "plugin", "t", env)
chunk()
```

An environment determines which names the code can use. It does not limit what a function in it can do. A plugin that receives `io` to read its input can also overwrite any file that the process can write.

Lus keeps environment tables and adds [permissions](#permissions). A permission applies to an operation whatever code calls it. A coroutine starts with the permissions of its creator. A change of permissions inside a coroutine affects that coroutine only. To run code with fewer permissions, a program therefore creates a coroutine. Inside the coroutine, `pledge` with the prefix `~` rejects a permission that the code must not use. `"seal"` then prevents any later pledge. In the following code, `chunk` is the plugin that the Lua example loads. The plugin still has the `io` library in its environment. An attempt to write a file or to load more code raises a permission error.

```lus nocheck
local co = coroutine.create(function()
    pledge("~fs:write", "~load", "seal")
    return chunk()
end)
print(coroutine.resume(co))
```

The code that created the coroutine keeps its own permissions. [Permissions in coroutines](/manual/permissions#permissions-in-coroutines) shows the complete program and states the rules. [Permissions](/manual/permissions) is the complete reference.

The `lus` executable includes these tools as commands, so every project has the same tools at the same version as the runtime.

## The implementation

The reference implementation of Lua is an interpreter written in portable ISO C. It runs on nearly any platform that has a C compiler. Its source is small enough to read in full.

The [Lus runtime](/manual/guide#internals) is written in Zig and has three tiers. Every function starts in an interpreter. On macOS and Linux, a baseline JIT compiler translates a function that runs often to machine code for aarch64 or x86-64. An optimizing tier then recompiles the functions that continue to run often, using the types of the values that it has recorded. The three tiers give the same results, so a program needs no change to use them. The WebAssembly build of Lus has an interpreter and a compiler that produces WebAssembly. A generational garbage collector manages memory. `collectgarbage` is still available.

Lua is designed as a small, portable core. Lus has a larger runtime, which gives it more speed and a complete standard library.
