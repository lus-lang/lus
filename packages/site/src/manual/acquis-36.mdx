Lus 2.0 gives the `number` type two exact subtypes beside integers and floats. A _bigint_ is an integer of any size, and a _decimal_ is a base 10 number that keeps exactly the digits it was given. Both are ordinary numbers: they work with the arithmetic and comparison operators, they compare equal to integers and floats of the same value, and the virtual machine handles them directly without a library call.

## Literals

A decimal or hexadecimal integer literal followed directly by `n` is a bigint. A numeric literal in decimal notation followed directly by `d` is a decimal, and it keeps its digits exactly as written, so `1.50d` has two fractional digits.

```lus
global print, math

print(2n ^ 100)                       --> 1267650600228229401496703205376
print(0xffn, math.type(0xffn))        --> 255  bigint
print(1.50d, 1e-2d, 3d)               --> 1.50  0.01  3
print(math.type(1.5d))                --> decimal
```

The `n` suffix applies only to integer literals, so `1.5n` and `1e3n` are malformed numbers. Hexadecimal digits include `d`, so `0xffd` is the integer 4093, and a hexadecimal float such as `0x1p4` takes no suffix. An integer literal that overflows 64 bits without a suffix becomes a float, as in Lua.

## The four subtypes

`math.type` reports which of the four subtypes a number has.

| Subtype | `math.type` | Representation | Literal |
| --- | --- | --- | --- |
| integer | `"integer"` | 64-bit two's complement | `42`, `0xff` |
| float | `"float"` | IEEE 754 binary64 | `1.5`, `1e9` |
| bigint | `"bigint"` | arbitrary precision integer | `42n`, `0xffn` |
| decimal | `"decimal"` | arbitrary precision base 10 coefficient with a 32-bit exponent | `1.50d`, `3d`, `1e-2d` |

Integer arithmetic wraps around on overflow, exactly as in Lua, which keeps hashing and bit manipulation predictable and keeps the integer fast path to a single machine instruction. A program that needs exact results beyond 64 bits uses bigints.

```lus
global print, math, bigint

print(math.maxinteger + 1 == math.mininteger)  --> true
print(bigint(math.maxinteger) + 1)             --> 9223372036854775808
```

## Arithmetic

Arithmetic between two subtypes picks the result subtype from this table, where rows and columns are the operand subtypes.

| | integer | float | bigint | decimal |
| --- | --- | --- | --- | --- |
| **integer** | integer | float | bigint | decimal |
| **float** | float | float | float | error |
| **bigint** | bigint | float | bigint | decimal |
| **decimal** | decimal | error | decimal | decimal |

Decimal arithmetic is exact for addition, subtraction, and multiplication, so the classic rounding surprise of binary floats does not occur.

```lus
global print

print(0.1d + 0.2d == 0.3d)   --> true
print(1.10d + 2.205d)        --> 3.305
print(1.5d * 2)              --> 3.0
```

Mixing a decimal and a float raises the error `attempt to mix decimal and float in arithmetic`. A decimal holds an exact base 10 value and a float an approximate base 2 value, so the program states which one it wants by converting with `decimal(x)` or `tonumber(x)`.

```lus
global print

print(catch 1.5d + 1.5)      --> false  ...: attempt to mix decimal and float in arithmetic
```

The `/` operator produces a float for integers and bigints, as in Lua. For decimals it produces a decimal with up to 34 significant digits, rounded half to even. The `//` and `%` operators keep the subtype from the table, and floor toward negative infinity for bigints exactly as they do for integers. Exponentiation produces a float, except that a decimal or bigint base with a non-negative integer exponent gives an exact result.

```lus
global print

print(1d / 3d)               --> 0.3333333333333333333333333333333333
print(10d / 4d)              --> 2.5
print(-7n // 2n, -7n % 2n)   --> -4  1
print(2d ^ 10)               --> 1024
```

The bitwise operators accept integers and bigints. On integers they act on 64 bits. When either operand is a bigint they act on the infinite two's complement representation and produce a bigint.

```lus
global print

print(1n << 64)              --> 18446744073709551616
print(~0n, 5n & 3)           --> -1  1
```

## Comparison and table keys

All four subtypes compare by mathematical value, so `1 == 1.0`, `1 == 1n`, and `1n == 1.00d` are all true. A decimal also compares exactly with a float, even though arithmetic between them is an error, so `0.5d == 0.5` is true and `0.1d == 0.1` is false.

A number used as a table key is normalized first. A float or decimal with an integral value and a bigint that fits in 64 bits all become the matching integer key, so `t[1]`, `t[1.0]`, `t[1n]`, and `t[1d]` name the same slot.

```lus
global print

local t = {}
t[1] = "one"
print(t[1.0], t[1n], t[1d])  --> one  one  one
```

## Conversions

Two global functions build exact numbers, and the standard conversions accept them.

- `bigint(x)` converts an integer, an integral float, a decimal with an integral value, or a numeric string to a bigint. A number without an integer value raises an error.
- `decimal(x)` converts an integer, a bigint, or a numeric string to a decimal exactly. A float converts through the shortest decimal string that reads back as the same float, so `decimal(0.1)` is `0.1d`.
- `math.tointeger(x)` returns an integer when `x` has an integral value that fits in 64 bits, whatever its subtype.
- `tostring` prints a bigint in decimal without a suffix, and a decimal with exactly its stored digits.

```lus
global print, bigint, decimal, math

print(bigint("123456789012345678901234567890") * 2)  --> 246913578024691357802469135780
print(decimal("2.50"), decimal(1 / 3))                --> 2.50  0.3333333333333333
print(math.tointeger(5n), math.type(math.tointeger(5n)))  --> 5  integer
```

## JSON

`fromjson` decodes numbers into integers and floats by default. With the option `{ exact = true }` it decodes integers that overflow 64 bits as bigints and numbers with a fraction or an exponent as decimals. `tojson` writes bigints and decimals with their exact digits, so a document read with `exact` writes back exactly as it was.

```lus
global print, fromjson, tojson

local doc = fromjson('{"price": 19.90, "id": 123456789012345678901234567890}', { exact = true })
print(doc.price, doc.id)     --> 19.90  123456789012345678901234567890
print(tojson({ total = doc.price * 3 }))  --> {"total":59.70}
```

## Motivation

### Exact money and identifiers

Prices, balances, and measurements written in base 10 are the most common numbers that binary floats cannot hold exactly. Database keys, cryptographic values, and JSON documents from other systems routinely carry integers wider than 64 bits. Decimals and bigints represent both exactly, and the JSON `exact` option carries them through a round trip without losing a digit.

### Numbers in the virtual machine

Bigints and decimals are subtypes of `number`, written with a literal suffix and handled by the virtual machine. Code that works with numbers works with them unchanged, comparisons and table keys follow mathematical value, and the explicit error on mixing decimals with floats keeps the choice between exact and approximate arithmetic visible in the program.

### Performance

Integers and floats stay inline in every value, and the quickened arithmetic instructions handle them without looking at heap state. A bigint or decimal operand makes the fast path hand over to the generic path, which dispatches on the subtype table above. Programs that use only integers and floats pay nothing for the exact subtypes.
