Lus 2.0 gives text and binary data a type each. A string holds text: every string is well formed WTF-8, and every string operation counts characters. A [vector](/manual/acquis-15) holds raw bytes: binary file reads, compressed data, packed structures, network reads, and compiled chunks are all vectors.

## Strings are text

Every string is well formed WTF-8, the superset of UTF-8 that also encodes lone surrogate code points. WTF-8 represents any sequence of Unicode code points, including the unpaired surrogates that occur in Windows file names and in UTF-16 data, so text from any of those sources round trips without loss.

A character is one Unicode code point, and every string operation indexes by character. `#s` and `string.len` return the number of characters. Positions in `string.sub`, slices, `string.find`, `string.match`, `string.gmatch`, and `string.gsub` are character positions. `string.byte` returns code points, `string.char` builds a string from code points, and `string.reverse` reverses characters.

```lus
global print, string

local s = "héllo, wörld"
print(#s, s:sub(2, 2), s[2, 5])          --> 12  é  éllo
print(s:find("ö"), s:reverse())          --> 9  dlröw ,olléh
print(s:byte(2), string.char(233, 0x1F600))  --> 233  é😀
```

`string.upper` and `string.lower` change the ASCII letters and leave every other character as it is. Patterns match whole characters. The class `.` matches one character, a set such as `[éà]` may contain any characters, and a range such as `[α-ω]` compares code points. The classes `%a`, `%d`, `%l`, `%s`, `%u`, `%w`, `%x`, `%p`, and `%c` describe ASCII characters.

```lus
global print

print(("añb"):gsub(".", "%0-"))          --> a-ñ-b-  3
print(("éa"):upper())                    --> éA
```

A string literal is text too. The escapes `\xNN` and `\ddd` produce the bytes of a UTF-8 sequence, and the literal as a whole must decode, so `"\xC3\xA9"` is `"é"` and a literal whose bytes are not valid text is a compile error that suggests a vector. `\u{XXXX}` writes any code point, including a surrogate.

Concatenating a string that ends with a lead surrogate and a string that starts with a trail surrogate joins the pair into one supplementary character, as WTF-8 requires.

```lus
global print

local joined = "a\u{D800}" .. "\u{DC00}b"
print(joined, #joined)                   --> a𐀀b  3
```

## Vectors are bytes

Byte level data lives in vectors. `vector.fromstring` returns the WTF-8 bytes of a string, and `vector.tostring` decodes bytes back into a string. Vector offsets are zero based: `vector.tostring(v, i, j)` decodes the bytes from offset `i` up to, but not including, offset `j`. Its mode `"strict"`, the default, raises an error that names the byte offset of the first invalid sequence. The mode `"lossy"` replaces each invalid sequence with U+FFFD.

```lus
global print, vector

local v = vector.fromstring("héllo")
print(#v, vector.get(v, 1), vector.get(v, 2))  --> 6  195  169
print(vector.tostring(v))                      --> héllo
print(vector.tostring(v, 0, 2, "lossy"))       --> h�
print(catch vector.tostring(v, 0, 2))          --> false  ...: invalid UTF-8 at byte 1
```

Every library function that produces raw bytes returns a vector, and every function that reads raw bytes accepts one.

- `string.pack` returns a vector, and `string.unpack` and `vector.unpack` read vectors.
- The [`vector.archive`](/manual/acquis-26) compressors accept a string or a vector and return a vector. The decompressors accept a vector or a string and return a vector, which `vector.tostring` turns back into text.
- [`string.transcode`](/manual/acquis-8) returns a vector when the target is a byte encoding such as `"utf-16le"` or `"latin1"`, and a string when the target is a text encoding such as `"utf-8"`, `"base64"`, or `"hex"`. Its input may be either.
- `string.dump` returns a vector, and `load` accepts that vector as a binary chunk.
- TCP and UDP reads and the body returned by `network.fetch` are vectors.

```lus
global print, string, vector

local packed = string.pack("<i4d", 7, 0.5)
print(#packed, string.unpack("<i4d", packed))  --> 12  7  0.5  13

local zipped = vector.archive.gzip.compress("hello hello hello")
print(vector.tostring(vector.archive.gzip.decompress(zipped)))  --> hello hello hello

local utf16 = string.transcode("hé", "utf-8", "utf-16le")
print(#utf16, string.transcode(utf16, "utf-16le", "utf-8"))     --> 4  hé
```

String interpolation produces text, so interpolating a vector raises an error that points to `vector.tostring`. A program decodes the bytes explicitly and chooses between strict and lossy decoding.

## Files and other boundaries

A file opened in binary mode, with `"b"` in its mode, reads vectors. A file opened in text mode reads strings and validates them, and a read that meets invalid input raises an error naming the byte offset. Passing `{ lossy = true }` as the third argument of `io.open` replaces each invalid sequence with U+FFFD instead. Writing accepts strings and vectors in either mode.

```lus
global io, print, pledge, vector

pledge("fs")

local out = io.open("data.bin", "wb")
out:write(vector.fromstring("bytes"), "and text")
out:close()

local bin <close> = io.open("data.bin", "rb")
local all = bin:read("a")
print(#all, vector.get(all, 0))          --> 13  98
```

Command line arguments, environment variables, and file system paths decode as WTF-8 on Windows and as UTF-8 with lossy replacement on other systems, so they are always strings.

## Compiled chunks

`string.dump` serializes a function into a vector, and `load` accepts a vector as a binary chunk. The chunk mode of `load` decides which kinds of chunk it accepts: `"t"` for text only, `"b"` for binary only, and `"bt"`, the default, for both. Loading code requires the `load` permission. Text from an untrusted source belongs in mode `"t"`, since a binary chunk is a trusted build artifact.

```lus
global print, string, load, pledge

pledge("load")

local chunk = string.dump(function(x) return x * 2 end)
local double = load(chunk, "double", "b")
print(double(21))                        --> 42
print(load(chunk, "double", "t"))        --> nil  attempt to load a binary chunk (mode is 't')
```

## Motivation

### One meaning per type

A string in Lus 2.0 always means text, and a vector always means bytes. Every string function can therefore count, index, and match characters, a slice never splits a character, and printing or interpolating a string always shows readable text. Code that handles binary data says so through its types, and the decoding step between bytes and text is a visible call with a chosen error mode.

### Lossless Unicode

WTF-8 covers every sequence of code points that real systems produce, including the unpaired surrogates of Windows paths and UTF-16 data. Text read from any of those sources survives a round trip through Lus unchanged, and the concatenation rule keeps surrogate pairs canonical.

### Fast character indexing

Each string records its byte length, its character count, and whether it is pure ASCII. An ASCII string indexes any character in constant time. A non-ASCII string builds a small index on its first indexed access, recording the byte offset of every 64th character, so any character is found with one lookup and a short scan. Validation and character counting use vectorized loops.
