> In Lus 2.0, `lus build SCRIPT` creates standalone executables. [Acquis 39](/manual/acquis-39) describes the command alongside the other developer tools.

Lus can bundle scripts and their dependencies into the interpreter executable itself, creating standalone binaries that run without external files.

## Basic Usage

Use `lus build` to create a standalone executable from a script:

```bash
lus build app.lus
```

This creates an executable named `app` (or `app.exe` on Windows) that runs the bundled script when executed. `-o FILE` names the executable explicitly.

```bash
./app
```

The command compiles the script, finds every `require` whose argument is a string literal, and bundles the modules those names resolve to through the module path, recursively. Names that resolve to no file, such as standard library modules, are left to the usual searchers at run time.

## Including Files

Use `--include` to bundle additional files, for modules that no literal `require` names:

```bash
lus build app.lus --include lib/utils.lus --include lib/config.lus
```

The bundled modules are available via their derived module names:

```lus nocheck
-- app.lus
local utils = require("utils")   -- loads bundled lib/utils.lus
local config = require("config") -- loads bundled lib/config.lus
```

### Module Aliases

Use the `:alias` syntax to specify a custom module name:

```bash
lus build app.lus --include vendor/json.lus:json
```

```lus nocheck
-- app.lus
local json = require("json")  -- loads bundled vendor/json.lus
```

## Including Directories

Entire directories can be included, with files recursively bundled using dot-notation module names:

```bash
lus build app.lus --include lib
```

```lus nocheck
-- app.lus
local http = require("lib.http")      -- loads lib/http.lus
local utils = require("lib.utils")    -- loads lib/utils.lus
local sub = require("lib.sub.module") -- loads lib/sub/module.lus
```

Only `.lus` and `.lua` files are included from directories.

## Module Resolution

Bundled modules are part of the program. When `require()` is called, bundled modules are checked before the filesystem, take precedence over same-named files in the working directory, and load without any permission.

## Preserved Options

Permissions given with `-P` and compile-time flags given with `-F` are baked into the executable and applied every time it runs:

```bash
lus build app.lus -P fs:read -P network
./app  # runs with the fs:read and network permissions
```

The executable grants nothing implicitly, so the program runs with exactly the permissions it pledges plus those given at build time.

## Runtime Arguments

Arguments passed to the standalone binary are available via the `arg` table and `...`:

```bash
./app foo bar baz
```

```lus nocheck
-- app.lus
print(arg[0])  -- "./app"
print(arg[1])  -- "foo"
print(arg[2])  -- "bar"
print(...)     -- "foo", "bar", "baz"
```
