The `fs` library manages files, directories, and symbolic links. A program uses it to list or create a directory and to copy, move, or remove an entry. Its `fs.path` functions build and split paths so that the same code runs on POSIX systems and on Windows. The [`io` library](/manual/api#io-library) reads and writes the contents of a file.

Every `fs` function that touches the filesystem requires the `fs:read` or `fs:write` [permission](/manual/permissions) for each path it uses. A function that fails raises an error, as [Errors](#errors) describes. A relative path is resolved against the working directory of the process.

## Reading and writing files

[`io.open(path, mode)`](/manual/api#io.open) opens a file and returns a file handle. The mode `"r"`, the default, reads, `"w"` creates the file or empties it and then writes, and `"a"` writes at the end of the file. A handle declared with the `<close>` attribute closes when its block ends, including when an error ends the block.

The following program writes two lines to a file, then reads the file once as a whole and once line by line.

```lus
pledge("fs")

local path = os.tmpname()

do
    local out <close> = assert(io.open(path, "w"))
    out:write("first line\n", "second line\n")
end

do
    local input <close> = assert(io.open(path))
    print(#input:read("a"))  --> 23
end

for line in io.lines(path) do
    print(line)
end

--> first line
--> second line
fs.remove(path)
```

`io.open` returns `nil` and a message when it cannot open the file, which is why the example wraps it in `assert`. A read or a write that the operating system refuses, such as a write to a full disk, returns `nil`, the message, and the number of the error, as in Lua, so a program that must notice the failure wraps the call in `assert` too. The iterator of `io.lines` raises such an error instead, which ends its loop. `read("a")` returns the whole file. [`io.lines`](/manual/api#io.lines) reads a file line by line and closes it after the last line. Reading requires `fs:read` for the path and writing requires `fs:write`. [Files](/manual/text#files) describes reading bytes and text in other encodings.

[`os.tmpname()`](/manual/api#os.tmpname) creates an empty temporary file and returns its path. A temporary file holds data that a program keeps only while it runs, so the program removes the file with `fs.remove` when it is done.

## Listing a directory

[`fs.list(path, glob)`](/manual/api#fs.list) returns an array with the name of every entry in the directory at `path`. Each name is the name alone, without the directory, so a program joins each one to `path` before it uses it. The array excludes `.` and `..`. The order of the names is unspecified.

The following program creates a directory with two files and lists it, sorting the names because their order is unspecified.

```lus
pledge("fs")

local base = os.tmpname()
local dir = `$base.d`
fs.createdirectory(dir)
io.open(fs.path.join(dir, "a.txt"), "w"):close()
io.open(fs.path.join(dir, "b.txt"), "w"):close()

local names = fs.list(dir)
table.sort(names)
print(table.concat(names, " "))  --> a.txt b.txt
fs.remove(dir, true)
fs.remove(base)
```

A _glob_ is a pattern that selects files by extension or by prefix. With a `glob`, `fs.list` returns only the names that match it. In a glob, `*` matches any sequence of characters, including the empty one, while `?` matches exactly one character. `[abc]` matches one of the listed characters, `[a-z]` one character of the range, and `[!abc]` one character that is not listed. `{json,md}` stands for each of its comma separated alternatives in turn. Every other character matches itself. A name that starts with `.` matches `*` like any other name.

The following program counts the JSON files in a directory and finds the configuration file whose number has one digit.

```lus
pledge("fs")

local base = os.tmpname()
local dir = `$base.d`
fs.createdirectory(dir)

for _, name in ipairs({ "config1.json", "config22.json", "notes.md" }) do
    io.open(fs.path.join(dir, name), "w"):close()
end

print(#fs.list(dir, "*.json"))  --> 2
print(fs.list(dir, "config?.json")[1])  --> config1.json
fs.remove(dir, true)
fs.remove(base)
```

A glob that contains `/` or a `**` segment reaches below `path`, and `fs.list` then returns paths relative to `path` with `/` between their segments. A `**` segment matches any number of directories, including none, so `**/*.lus` matches the Lus files at every depth. Symbolic links to directories are listed without being followed.

The following program lists the Markdown and JSON files of a small tree.

```lus
pledge("fs")

local base = os.tmpname()
local dir = `$base.d`
fs.createdirectory(fs.path.join(dir, "docs", "api"), true)

for _, name in ipairs({
    "README.md",
    "package.json",
    "docs/intro.md",
    "docs/api/fs.md",
    "docs/logo.png",
}) do
    io.open(fs.path.join(dir, name), "w"):close()
end

local found = fs.list(dir, "**/*.{md,json}")
table.sort(found)
print(table.concat(found, " "))  --> README.md docs/api/fs.md docs/intro.md package.json
fs.remove(dir, true)
fs.remove(base)
```

`fs.list` requires `fs:read` for `path`. It raises `"cannot list directory PATH: No such file or directory"` when the directory does not exist and `"PATH is not a directory"` when `path` names a file.

## Walking a directory tree

[`fs.walk(dir, options)`](/manual/api#fs.walk) returns an iterator that visits every entry below `dir` and reads each directory when it reaches it, so a loop that stops early never reads the rest of the tree. Each step gives the path of the entry joined to `dir`, then `"directory"` or `"file"`, then whether the entry is a symbolic link. The walk is depth first, sorts the names within each directory, and gives a directory before the entries inside it, so a walk of the same tree gives the same sequence on every system.

The options select what the walk visits. `depth` limits how far it goes, with `1` for the entries of `dir` alone. `glob` keeps the entries that match it: a glob without `/` matches the name of an entry at any depth, and any other glob matches the path relative to `dir`. `exclude` is a glob or an array of globs whose matches are neither reported nor entered. `links = "follow"` enters symbolic links to directories, and `errors = "skip"` leaves out a subdirectory that cannot be read where the walk would otherwise raise an error.

The following program adds up the sizes of the Lus files in a project and leaves out a directory of dependencies.

```lus
pledge("fs")

local base = os.tmpname()
local dir = `$base.d`
fs.createdirectory(fs.path.join(dir, "src"), true)
fs.createdirectory(fs.path.join(dir, "deps"), true)
local files = {
    ["main.lus"] = "print(1)\n",
    ["src/util.lus"] = "return {}\n",
    ["deps/big.lus"] = string.rep("x", 1000),
}

for name, text in pairs(files) do
    local f = io.open(fs.path.join(dir, name), "w")
    f:write(text)
    f:close()
end

local total = 0

for path in fs.walk(dir, { glob = "*.lus", exclude = "deps" }) do
    local f = io.open(path, "r")
    total = total + #f:read("a")
    f:close()
end

print(total)  --> 19
fs.remove(dir, true)
fs.remove(base)
```

`fs.walk` requires `fs:read` for `dir`, and it enters a subdirectory only when `fs:read` covers it.

## Watching for changes

[`fs.watch(path, options)`](/manual/api#fs.watch) returns a coroutine that hands over the changes to the files under `path`. Each resume waits for the next change, then returns `true` and an event whose `kind` is `"create"`, `"modify"`, `"remove"`, or `"rescan"`, and whose `path` is the path that changed. A `"rescan"` event means that the system dropped events, so the program should look at the tree again. Events of one path that follow each other within 50 milliseconds merge into one, so an editor that saves a file in several steps produces one event.

The watch covers the entries of `path`, and with `recursive = true` every directory below it. `glob` keeps the events whose path matches it. Closing the coroutine stops the watch. Resumed inside a detached coroutine, the wait suspends that coroutine as a [suspension point](/manual/concurrency#suspension-points) does.

The following program rebuilds a site whenever one of its pages changes.

```lus nocheck
pledge("fs")

local changes = fs.watch("pages", {recursive = true, glob = "*.md"})
while true do
    local _, event = coroutine.resume(changes)
    print(event.kind, event.path)
    rebuild()
end
```

`fs.watch` requires `fs:read` for `path` and never delivers an event of a path that `fs:read` does not cover.

## Inspecting a path

[`fs.type(path)`](/manual/api#fs.type) reports whether `path` is a directory or a file, which a program needs to know before it lists or opens an entry. It returns two values. The first is `"directory"` for a directory and `"file"` for anything else. The second is `true` when `path` is a symbolic link, in which case the first value is the type of its target, or `"file"` when the target does not exist.

The following program inspects a directory, a file, and a link to that file.

```lus
pledge("fs")

local base = os.tmpname()
local dir = `$base.d`
fs.createdirectory(dir)
io.open(fs.path.join(dir, "data.txt"), "w"):close()
fs.createlink(fs.path.join(dir, "shortcut"), "data.txt")

print(fs.type(dir))  --> directory  false
print(fs.type(fs.path.join(dir, "data.txt")))  --> file  false
print(fs.type(fs.path.join(dir, "shortcut")))  --> file  true
fs.remove(dir, true)
fs.remove(base)
```

`fs.type` raises `"path 'PATH' does not exist"` when nothing exists at `path`. A program tests whether a path exists by wrapping the call in [`catch`](/manual/guide#errors), whose first result is `false` when the call raised an error.

```lus
pledge("fs:read")

local function exists(path)
    return (catch fs.type(path))
end

print(exists("."), exists("no-such-file"))  --> true  false
```

[`fs.follow(path)`](/manual/api#fs.follow) returns the target of the symbolic link at `path` exactly as the link stores it. It raises `"'PATH' is not a symbolic link"` for any other entry. Both functions require `fs:read` for `path`.

## Creating directories

[`fs.createdirectory(path, recursive)`](/manual/api#fs.createdirectory) creates a directory. Without `recursive`, the parent must exist and `path` must not. Otherwise the call raises `"cannot create directory 'PATH': parent does not exist"` or `"cannot create directory 'PATH': already exists"`.

Both calls under `catch` in the following program fail, the first because the directory exists and the second because its parent is missing.

```lus
pledge("fs")

local base = os.tmpname()
local dir = `$base.d`
fs.createdirectory(dir)
print((catch fs.createdirectory(dir)))  --> false
print((catch fs.createdirectory(`$dir/missing/child`)))  --> false
fs.remove(dir)
fs.remove(base)
```

With `recursive` set to `true`, the call creates every missing directory along `path` and succeeds when the whole path already exists. This is the form for a program that needs a directory to exist before it writes into it, such as an output or cache directory. A component of `path` that exists as a file raises an error. A `..` component in a recursive `path` raises `"cannot create directory 'PATH': '..' is denied"`.

The following program creates a tree of three directories, then calls `fs.createdirectory` again, which finds the tree in place and succeeds.

```lus
pledge("fs")

local base = os.tmpname()
local tree = `$base.d`
fs.createdirectory(`$tree/a/b/c`, true)
fs.createdirectory(`$tree/a/b/c`, true)
print((fs.type(`$tree/a/b/c`)))  --> directory
fs.remove(tree, true)
fs.remove(base)
```

`fs.createdirectory` requires `fs:write` for `path`. In recursive mode, `fs:write` must also cover each directory that the call creates.

## Copying and moving

[`fs.copy(source, dest)`](/manual/api#fs.copy) copies the contents of the file at `source` into a new file at `dest`. It never replaces an existing file, so a copy cannot destroy data. A `dest` that exists raises `"target 'DEST' already exists"`. The source must be a file. A source that is a directory raises an error. If the copy fails partway, `fs.copy` removes the partial file at `dest` before it raises the error.

The following program makes a backup of a file, then copies it again, which fails because the backup exists.

```lus
pledge("fs")

local original = os.tmpname()
local backup = `$original.bak`
io.open(original, "w"):write("contents"):close()
fs.copy(original, backup)

local copy <close> = io.open(backup)
print(copy:read("a"))  --> contents
print((catch fs.copy(original, backup)))  --> false
fs.remove(original)
fs.remove(backup)
```

`fs.copy` requires `fs:read` for `source` and `fs:write` for `dest`.

[`fs.move(source, dest)`](/manual/api#fs.move) renames a file or a directory, which moves the entry when `dest` is in another directory of the same filesystem. Like `fs.copy`, it keeps an existing entry by default, so a `dest` that exists raises `"cannot move to 'DEST': target already exists"`. With a third argument of `{ replace = true }`, the move replaces `dest` in one step, which [Durable writes](#durable-writes) builds on. A missing `source` raises `"cannot move 'SOURCE': source does not exist"`. A move between two filesystems, such as two disks, raises an error that ends in `cross-device move`, so a program that needs such a move copies the file and removes the original.

The following program renames a file and then moves it into an archive directory.

```lus
pledge("fs")

local base = os.tmpname()
local archive = `$base.archive`
fs.createdirectory(archive)
fs.move(base, `$base.final`)
fs.move(`$base.final`, fs.path.join(archive, "final.txt"))
print((fs.type(fs.path.join(archive, "final.txt"))))  --> file
fs.remove(archive, true)
```

`fs.move` requires `fs:read` and `fs:write` for `source` and `fs:write` for `dest`.

## Removing files and directories

[`fs.remove(path, recursive)`](/manual/api#fs.remove) removes a file, a symbolic link, or an empty directory. A directory that still has entries raises `"cannot remove directory 'PATH': not empty"` unless `recursive` is `true`, in which case the call removes the directory and everything below it. A missing `path` raises `"cannot remove 'PATH': path does not exist"`.

In the following program, the plain call fails to remove a directory that holds a file, then the recursive call succeeds.

```lus
pledge("fs")

local base = os.tmpname()
local scratch = `$base.d`
fs.createdirectory(`$scratch/deep`, true)
io.open(`$scratch/deep/file.txt`, "w"):close()

print((catch fs.remove(scratch)))  --> false
fs.remove(scratch, true)
print((catch fs.type(scratch)))  --> false
fs.remove(base)
```

`fs.remove` never follows a symbolic link, so removing a link leaves its target in place. A recursive removal removes each link inside the tree without touching its target, so it never deletes files outside the tree it was given.

The permission check follows the same rule. `fs.remove` requires `fs:write` for the location of `path` itself, so a grant that covers a link permits removing the link even when its target lies outside the grant.

## Symbolic links

A _symbolic link_ is an entry that points to another path, so that opening the link opens its target. [`fs.createlink(link, target)`](/manual/api#fs.createlink) creates a symbolic link at `link` that points to `target`. The link stores `target` as given, so a relative target is resolved against the directory of the link when the link is used. `fs.follow` returns the stored target.

The following program creates a link named `alias` to a file in the same directory.

```lus
pledge("fs")

local base = os.tmpname()
local dir = `$base.d`
fs.createdirectory(dir)
io.open(fs.path.join(dir, "real.txt"), "w"):close()
local alias = fs.path.join(dir, "alias")
fs.createlink(alias, "real.txt")

print(fs.follow(alias))  --> real.txt
print(fs.type(alias))  --> file  true
fs.remove(dir, true)
fs.remove(base)
```

`fs.createlink` requires `fs:write` for both `link` and `target`, so a script cannot create a link that points outside the paths it may write. A failure raises an error of the form `"failed to create symlink 'LINK' -> 'TARGET': REASON"`.

## Paths

POSIX systems separate the parts of a path with `/` and Windows separates them with `\`, so a path built with `dir .. "/" .. name` is correct on only some systems. The functions of [`fs.path`](/manual/api#fs.path) build and split paths with the separator of the platform the program runs on. They compute on the path strings alone, so they require no permission. They accept `/` as a separator on every platform and `\` on Windows as well.

[`fs.path.join(...)`](/manual/api#fs.path.join) joins its arguments with the platform separator, skipping empty arguments and adding no separator where one is already present. An absolute argument replaces everything before it. Only the first of the following calls gives a result that depends on the platform, so its comments show the result on POSIX systems and on Windows.

```lus
print(fs.path.join("dir", "sub", "file.txt"))
-->(posix) dir/sub/file.txt
-->(windows) dir\sub\file.txt
print(fs.path.join("relative", "/absolute"))  --> /absolute
print(fs.path.join("a/", "", "b"))  --> a/b
```

[`fs.path.split(path)`](/manual/api#fs.path.split) returns an array of the components between the separators. The first component of an absolute path is the empty string. A trailing separator adds no component.

```lus
local parts = fs.path.split("/usr/local/bin")
print(#parts, parts[1] == "", parts[2], parts[4])  --> 4  true  usr  bin
```

[`fs.path.name(path)`](/manual/api#fs.path.name) returns the part after the last separator, which is the file name. [`fs.path.parent(path)`](/manual/api#fs.path.parent) returns the part before it, which is the directory that holds the entry. The parent of a path without a separator is `"."`, while the parent of an entry directly under the root is the root. A path that ends in a separator has the empty string as its name.

```lus
print(fs.path.name("/home/user/report.pdf"))  --> report.pdf
print(fs.path.parent("/home/user/report.pdf"))  --> /home/user
print(fs.path.parent("/etc"))  --> /
print(fs.path.parent("report.pdf"))  --> .
```

[`fs.path.separator`](/manual/api#fs.path.separator) is the separator of the platform, `"/"` on POSIX and `"\"` on Windows. [`fs.path.delimiter`](/manual/api#fs.path.delimiter) is the character that separates the entries of a list of paths such as the `PATH` environment variable, `":"` on POSIX and `";"` on Windows.

## Durable writes

A write returns when the operating system holds the new bytes in its memory. The system writes them to the disk later, in its own order. A killed process loses nothing that it wrote, because the system still holds those bytes. A crash of the system or a loss of power is different. It can lose any write that has not reached the disk, keep a later write while losing an earlier one, or keep part of a write. Two calls control when data reaches the disk.

- [`file:sync()`](/manual/api#file:sync) returns once the data and the size of the file are on the disk.
- [`fs.sync(dir)`](/manual/api#fs.sync) returns once the entries of the directory are on the disk. The name of a file is such an entry, so creating, renaming, and removing a file all change its directory.

A program that replaces a file with new contents uses four steps, in this order.

1. Write the new contents to a temporary file in the same directory as the target.
2. Sync the temporary file with `file:sync()`. The new contents are then complete on the disk.
3. Move the temporary file over the target with `fs.move(tmp, target, { replace = true })`. A reader now finds the new contents. A reader that opened the target earlier keeps the old ones.
4. Sync the directory with `fs.sync(dir)`. The new name is then on the disk.

After a crash at any point, the target holds either its complete old contents or its complete new contents. Step 2 keeps the new contents whole. Without it, the rename can reach the disk before the data, which leaves the target empty or partly written. Step 4 makes the replacement last. Without it, the target can return to its old contents after a crash, even though the program finished. The following function performs the four steps.

```lus
local function replace(path, contents)
    local tmp = `$path.tmp`
    local f = assert(io.open(tmp, "w"))
    assert(f:write(contents))
    assert(f:sync())
    f:close()
    fs.move(tmp, path, { replace = true })
    fs.sync(fs.path.parent(path))
end

pledge("fs")

local base = os.tmpname()
replace(base, "version 1\n")
replace(base, "version 2\n")
print(io.open(base):read("a"))  --> version 2
fs.remove(base)
```

A program that appends records to a log syncs the file after each record and before it reports the record as saved. A crash then keeps every reported record. Only the last record can arrive incomplete, so each record carries a length or a checksum that lets a reader drop an incomplete one. This holds on disks with the powersafe overwrite property, which the drives of current systems have. On a disk without it, a lost append can also damage the end of the record before it, in the same sector of 512 bytes.

Overwriting part of a file in place is not atomic, even with a sync. A crash can leave the region half old and half new, because a disk writes in sectors of 512 bytes and keeps any subset of the sectors of an unfinished write. A program that updates records in place keeps a journal, or stores its data in [SQLite](/manual/sqlite), which keeps one. SQLite commits a transaction atomically after any crash. It makes the commit durable when the database runs with `PRAGMA synchronous = FULL`, which syncs the log at each commit.

The crash tests of the runtime check each of these sequences. They stop a program at every file operation, with a kill and with a simulated power loss that follows the rules above. Then they check that the guarantees hold and that each step is needed.

## Errors

Every failure of an `fs` function raises an error object that is a string naming the operation, the path, and the reason. The reasons that the runtime writes itself, such as `already exists` and `not empty`, are the same on every platform, while other reasons, such as `No such file or directory`, come from the operating system. The message starts with the position of the call, which the following example removes with `match`.

```lus
pledge("fs")

local ok, err = catch fs.remove("nonexistent")
print(ok)  --> false
print(err:match("cannot.*"))  --> cannot remove 'nonexistent': path does not exist
```

## Copying a directory tree

`fs.copy` copies one file. The following function copies a whole directory by combining `fs.list`, `fs.type`, `fs.path.join`, and `fs.copy`, calling itself for each directory it finds.

```lus
local function copytree(src, dst)
    fs.createdirectory(dst)

    for _, name in ipairs(fs.list(src)) do
        local source = fs.path.join(src, name)
        local target = fs.path.join(dst, name)

        if fs.type(source) == "directory" then
            copytree(source, target)
        else
            fs.copy(source, target)
        end
    end
end

pledge("fs")

local base = os.tmpname()
fs.createdirectory(`$base.project/src`, true)
io.open(`$base.project/src/main.lus`, "w"):write("print(1)"):close()
copytree(`$base.project`, `$base.backup`)
print((fs.type(`$base.backup/src/main.lus`)))  --> file
fs.remove(`$base.project`, true)
fs.remove(`$base.backup`, true)
fs.remove(base)
```
