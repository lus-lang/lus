The `fromjson` and `tojson` global functions provide RFC 8259 parsing and serialization. Parsing accepts up to 1,000 nested arrays and objects. Serialization enforces the same ceiling and also follows the interpreter's C-call limit, which can reject a deeply nested table earlier with a C stack overflow.

## Parsing with `fromjson`

`fromjson` parses one JSON value and requires the complete input to be valid. It accepts a string or number. A numeric argument is converted to its textual form before parsing, while other argument types raise a type error.

```lus
local data = fromjson('{"name": "Alice", "age": 30}')
assert(data.name == "Alice")
assert(data.age == 30)
```

JSON values map to Lus values as follows.

```lus
fromjson("null")           -- nil
fromjson("true")           -- true
fromjson("42")             -- 42, an integer
fromjson("3.14")           -- 3.14, a float
fromjson('"hello"')        -- "hello"
fromjson("[1, 2, 3]")      -- {1, 2, 3}
fromjson('{"a": 1}')       -- {a = 1}
```

Number syntax determines the Lus subtype. Integer syntax produces an integer, while a decimal point or exponent produces a float. Values outside the supported integer or floating-point range raise a range error. Duplicate object keys keep the final value.

JSON null maps to `nil`. A null object field is therefore absent from the resulting table, and a null array element creates a hole. This mapping means a parse and serialize cycle can change the structure of JSON that contains null values.

### Parse errors

Invalid input raises an error with a byte position.

```lus
local ok, err = catch fromjson('{"invalid}')
assert(not ok)
assert(err:match("position"))
```

## Serializing with `tojson`

`tojson` serializes one Lus value.

```lus
local json = tojson({name = "Bob", scores = {95, 87, 92}})
local decoded = fromjson(json)
assert(decoded.name == "Bob")
assert(decoded.scores[2] == 87)
```

### Arrays and objects

Tables whose complete key set is a contiguous integer range from 1 through `n` become JSON arrays. The empty table is an empty array. Every other table uses object form, which writes string keys and omits keys of other types.

JSON object member order is unspecified. Examples that consume an object parse it and inspect fields by name.

```lus
tojson({10, 20, 30})           -- "[10,20,30]"
tojson({})                     -- "[]"

local object = fromjson(tojson({a = 1, b = 2}))
assert(object.a == 1 and object.b == 2)

local sparse = fromjson(tojson({1, nil, 3}))
assert(sparse[1] == nil and sparse[3] == nil)

local named = fromjson(tojson({1, 2, name = "pair"}))
assert(named.name == "pair")
```

### Special values

Non-finite numbers become JSON null.

```lus
tojson(math.huge)   -- "null"
tojson(-math.huge)  -- "null"
tojson(0 / 0)       -- "null"
```

Functions, threads, userdata, vectors, and enum values encode as `null` at the root or in an array. An object field holding one of these values is omitted.

```lus
local status = enum ready, done end
tojson(status.ready)                    -- "null"
tojson({status.ready})                  -- "[null]"
tojson({status = status.ready})         -- "{}"
```

## Filtering with `tojson`

The optional filter transforms values or omits fields.

```lus
local data = {
    name = "Alice",
    password = "secret",
    age = 30,
}

local json = tojson(data, function(key, value)
    if key == "password" then return nil end
    return value
end)
```

The filter is first called for the root with a `nil` key. It then receives integer keys for array elements and string keys for object fields. A returned table is traversed and filtered recursively. Returning `nil` for the root produces `"null"`. Errors from the filter propagate from `tojson`.

## Custom serialization with `__json`

A table can provide a `__json` metamethod that returns the value to serialize.

```lus
local Point = {}
Point.__index = Point
Point.__json = function(self)
    return {x = self.x, y = self.y}
end

local point = setmetatable({x = 10, y = 20, internal = "data"}, Point)
local decoded = fromjson(tojson(point))
assert(decoded.x == 10 and decoded.y == 20)
```

The returned value follows the normal serialization rules and may itself have a `__json` metamethod. Returning `nil` produces `"null"`. Errors raised by the metamethod propagate from `tojson`.

## References and round trips

Shared acyclic tables are written by value each time they appear. A circular reference raises an error.

```lus
local child = {value = 1}
local copies = fromjson(tojson({child, child}))
assert(copies[1].value == 1 and copies[2].value == 1)

local cycle = {}
cycle.self = cycle
local ok, err = catch tojson(cycle)
assert(not ok)
```

Supported primitives, contiguous arrays, and string-keyed objects round trip predictably. Whole-valued floats serialize without a decimal point, so they parse back as integers. JSON null follows the `nil` mapping described above. Applications that need a distinct null sentinel can represent it with an application-level value and a `__json` method.
