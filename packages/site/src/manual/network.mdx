The `network` library sends HTTP and HTTPS requests, opens TCP and UDP sockets, and serves HTTP. Every function that contacts the network checks a `network` [permission](/manual/permissions) for the host it contacts, and every function that receives data returns it as a [vector](/manual/guide#vector).

## Permissions

Each operation checks one subcapability of `network`, and `pledge("network")` grants all of them.

| Operation | Permission | Requested value |
| --- | --- | --- |
| `network.fetch` | `network:http` | The URL. |
| `network.tcp.connect`, `network.tcp.bind` | `network:tcp` | `host:port` |
| `network.udp.open`, `setsockname`, `sendto` | `network:udp` | `host:port`, or no value for an unbound socket |
| `network.serve` | `network:server` | `host:port` of the address it serves |

A permission with a value, such as `network:http=api.example.com/*` or `network:tcp=127.0.0.1:*`, permits only the hosts that match. [Restricting a permission to values](/manual/permissions#restricting-a-permission-to-values) gives the matching rules. `sendto` checks the permission for every destination, so a UDP grant for one host never permits datagrams to another.

## HTTP requests

[`network.fetch(url, method, headers, body)`](/manual/api#network.fetch) sends one HTTP or HTTPS request and returns three values: the integer status code, the response body as a vector, and a table of the response headers with lowercase names. The arguments after `url` are positional and optional. `method` defaults to `"GET"`, `headers` is a table from header names to values, and `body` is a string or a vector.

```lus nocheck
pledge("network:http")

local status, body, headers = network.fetch("https://httpbin.org/get")
print(status)                    --> 200
print(headers["content-type"])   --> application/json
local data = fromjson(vector.tostring(body))
```

A request with headers or a body passes the arguments in their positions.

```lus nocheck
local status, body = network.fetch(
    "https://httpbin.org/post",
    "POST",
    { ["Content-Type"] = "application/json" },
    tojson({ name = "Lus" })
)
```

`fetch` sends `Host`, `Connection: close`, and `User-Agent: Lus/1.0`, adds `Content-Length` when the body is not empty, and then sends the headers of the `headers` table. It returns every status the server answers with, so a 404 or a 500 is a result and not an error. A redirect returns its 3xx status together with its `location` header. Response bodies are limited to 64 MiB, and a larger body raises `"response body too large"`. HTTPS verifies the certificate of the server against the certificates of the system and raises an error when the verification fails.

A failure to reach the server or to read its response raises an error, such as `"cannot resolve 'invalid.host.example': Domain name not found"` or `"cannot connect to 127.0.0.1:1: Connection refused"`. A URL with a scheme other than `http` or `https` raises `"invalid URL: URL"`, and a URL, method, or header that contains a line break raises an error before anything is sent.

```lus nocheck
local ok, err = catch network.fetch("https://invalid.host.example")
if not ok then
    print("request failed: " .. err)
end
```

Outside a detached coroutine, `network.fetch` runs the [detached coroutines](/manual/concurrency#detached-coroutines) while it waits for the response, so the main chunk can fetch from a `network.serve` that runs in the same state. Inside a detached coroutine, `network.fetch` blocks the whole state while it waits, the other detached coroutines included, so a coroutine sends requests to a server of the same state through a TCP socket, as the example under [HTTP server](#http-server) does.

## TCP clients

[`network.tcp.connect(host, port)`](/manual/api#network.tcp.connect) opens a connection and returns a socket. `host` is a name or a numeric address. A connection that the system refuses or cannot reach raises an error such as `"cannot connect to HOST:PORT: Connection refused"`.

A TCP socket has these methods.

| Method | Effect |
| --- | --- |
| `send(data)` | Sends a string or a vector in full and returns the number of bytes sent. |
| `receive(pattern, max_bytes)` | Receives data as a vector, as described below. |
| `settimeout(seconds)` | Bounds every later wait of the socket, as described in [Timeouts](#timeouts). |
| `getsockname()` | Returns the local numeric address and port. |
| `getpeername()` | Returns the numeric address and port of the other end. |
| `close()` | Closes the connection. A second `close` does nothing. |

A method other than `close` on a closed socket raises `"attempt to use a closed socket"`. A failure of the connection itself during `send` or `receive`, such as a reset by the other end, returns `nil` and a message such as `"receive: Connection reset by peer"`. The collector closes a socket that nothing refers to any more, and a socket declared with the `<close>` attribute closes when its variable goes out of scope.

## Receiving from a TCP socket

[`socket:receive(pattern, max_bytes)`](/manual/api#tcp_socket:receive) reads according to one of three patterns and returns a vector.

| Pattern | Result | Limit |
| --- | --- | --- |
| A positive integer `n` | Exactly `n` bytes, or the bytes that remain when the connection ends first | `n` must be at most 1 MiB |
| `"*l"`, the default | One line, without its LF and an optional CR before it | 1 MiB, or `max_bytes` |
| `"*a"` | Everything up to the end of the connection | 64 MiB, or `max_bytes` |

At the end of the connection every pattern returns the bytes that remain, which is an empty vector once nothing remains. An integer that is zero, negative, or larger than 1 MiB raises `"invalid receive size: N"`, and any other pattern raises `"invalid receive pattern: PATTERN"`.

The optional positive integer `max_bytes` sets the limit of `"*l"` and `"*a"`. A line or a stream that exceeds its limit closes the socket and raises `"receive limit exceeded"`, so a peer that never sends a line break cannot make the program buffer without bound.

```lus nocheck
local request_line = socket:receive("*l", 8192)
local upload = socket:receive("*a", 8 * 1024 * 1024)
```

## TCP servers

[`network.tcp.bind(host, port, backlog)`](/manual/api#network.tcp.bind) binds a listening server and returns it. `backlog` is the number of connections the system queues before `accept` takes them, and defaults to 128. Port `0` lets the operating system choose a free port, and [`server:getsockname()`](/manual/api#tcp_server:getsockname) returns the bound numeric address and the port it chose.

A server has the methods `accept`, `settimeout`, `getsockname`, and `close`. `accept()` waits for the next connection and returns a TCP socket with the methods above.

The following program runs a server in a [detached coroutine](/manual/concurrency#detached-coroutines) and talks to it from the main chunk of the same program. The `receive` of the main chunk waits for the reply, and the server coroutine runs while it waits.

```lus
pledge("network")

local server = network.tcp.bind("127.0.0.1", 0)
local address, port = server:getsockname()

local greeter = coroutine.detach(coroutine.create(function()
    local client <close> = server:accept()
    local name = vector.tostring(client:receive("*l", 1024))
    client:send(`hello, $name\n`)
end))

local sock <close> = network.tcp.connect(address, port)
sock:send("Lus\n")
print(vector.tostring(sock:receive("*l")))   --> hello, Lus
assert(coroutine.resume(greeter))
server:close()
```

## UDP sockets

[`network.udp.open(port, address)`](/manual/api#network.udp.open) creates a UDP socket. With an `address`, or with a `port` other than `0`, the socket is bound to that local address and port at once. The address is a numeric IPv4 address and defaults to `0.0.0.0`. Without either argument the socket sends from a port that the system chooses, and `setsockname` may bind it once to a chosen address and port.

A UDP socket has these methods.

| Method | Effect |
| --- | --- |
| `sendto(data, address, port)` | Sends one datagram and returns the number of bytes sent. |
| `receive(size)` | Waits for one datagram and returns its data as a vector, the numeric address of the sender, and the port of the sender. |
| `setsockname(address, port)` | Binds an unbound socket. |
| `getsockname()` | Returns the local numeric address and port. |
| `settimeout(seconds)` | Bounds every later wait of the socket. |
| `close()` | Closes the socket. |

`receive(size)` returns at most `size` bytes of the datagram and discards the rest of it. `size` defaults to 8 KiB and must be between 1 and 1 MiB, and any other size raises `"invalid receive size: N"`. A socket binds once, and `setsockname` on a bound socket returns `nil` and an error message. A method other than `close` on a closed socket raises `"attempt to use a closed UDP socket"`.

```lus
pledge("network")

local receiver = network.udp.open(0, "127.0.0.1")
local _, port = receiver:getsockname()

local sender = network.udp.open()
print(sender:sendto("hello", "127.0.0.1", port))   --> 5

local data, address = receiver:receive()
print(vector.tostring(data), address)              --> hello  127.0.0.1

sender:close()
receiver:close()
```

## Timeouts

A _timeout_ bounds how long one operation of a socket or server may wait. `settimeout(seconds)` sets it for every later operation, and `seconds` may have a fraction. A negative value or NaN removes the timeout, which is also the state of a new socket. A timeout of `0` never waits, so an operation that cannot complete at once fails at once.

When a timeout runs out, the operation raises `"receive timeout"`, `"send timeout"`, `"accept timeout"`, or `"sendto timeout"`. The socket stays open and usable after a timeout.

```lus
pledge("network")

local server = network.tcp.bind("127.0.0.1", 0)
server:settimeout(0.05)
local ok, err = catch server:accept()
print(ok, err:match("accept timeout"))   --> false  accept timeout
server:close()
```

## Waiting inside detached coroutines

A _suspension point_ is an operation that, inside a detached coroutine, suspends that coroutine until its socket is ready while the other detached coroutines run. `connect`, `accept`, `send`, and `receive` on TCP, and `receive` and `sendto` on UDP, are suspension points. Outside a detached coroutine the same operation blocks its caller and runs the detached coroutines while it waits. A timeout bounds the wait in both cases. [Suspension points](/manual/concurrency#suspension-points) describes the scheduling in full.

## HTTP server

[`network.serve(host, port, handler, options)`](/manual/api#network.serve) serves HTTP/1.1 on `host` and `port` and calls `handler` once for every request. Every connection runs in a detached coroutine of its own, so a slow client never holds up the others, and connections stay open between requests unless the client asks to close them. `serve` blocks its caller for as long as the server runs.

```lus nocheck
pledge("network")

network.serve("127.0.0.1", 8080, function(req)
    if req.method == "GET" and req.path == "/" then
        return 200, "hello\n", { ["Content-Type"] = "text/plain" }
    end
    return 404, "not found\n"
end)
```

The second form, `network.serve(server, handler, options)`, serves on a server that `network.tcp.bind` returned. It lets a program bind port `0` and read the chosen port with `getsockname` before it serves. A server that `serve` bound itself closes when `serve` ends, and a server passed to it stays open until the program closes it. `serve` ends when the coroutine that called it is closed, or when accepting a connection fails for a reason other than a shortage of file descriptors or memory.

The following program serves in a detached coroutine and sends one request over a TCP socket from the main chunk.

```lus
pledge("network")

local server = network.tcp.bind("127.0.0.1", 0)
local _, port = server:getsockname()

local serving = coroutine.detach(coroutine.create(network.serve), server, function(req)
    return 200, `hello from $(req.path)`, { ["Content-Type"] = "text/plain" }
end)

local sock <close> = network.tcp.connect("127.0.0.1", port)
sock:send("GET /docs HTTP/1.1\r\nHost: localhost\r\nConnection: close\r\n\r\n")
local response = vector.tostring(sock:receive("*a"))
print(response:match("^HTTP/1.1 (%d+)"))   --> 200
print(response:match("\r\n\r\n(.*)$"))     --> hello from /docs

coroutine.close(serving)
server:close()
```

### Requests

The handler receives one table per request with five fields.

| Field | Value |
| --- | --- |
| `method` | The request method, such as `"GET"`. |
| `path` | The request target up to the first `?`, as the client sent it. |
| `query` | The text after the first `?`, or the empty string. |
| `headers` | A table from lowercase header names to their values. A header that repeats joins its values with `", "`. |
| `body` | The request body as a vector, which is empty for a request without a body. |

The server reads bodies with a `Content-Length` and bodies with `Transfer-Encoding: chunked`, and it answers `Expect: 100-continue`.

### Responses

The handler returns `status, body, headers`, in the order in which `network.fetch` returns them. `status` is an integer and defaults to 200. `body` is a string or a vector and defaults to an empty body. `headers` is a table from header names to strings or integers. The server adds `Date`, `Content-Length`, and `Connection` when the handler leaves them out, and it leaves the body out of the response to a `HEAD` request.

A handler may wait. A socket operation or a `coroutine.yield` inside it suspends its connection, and the other connections run in the meantime. A handler may take as long as it needs.

### Handler errors

When the handler raises an error, or returns values that make no response, such as a status that is not an integer, the server answers 500 with an empty body and closes that connection. The other connections continue. The server writes the error to standard error in the form `lus: network.serve: MESSAGE`, or passes the error object to the `on_error` function of the options.

```lus
pledge("network")

local server = network.tcp.bind("127.0.0.1", 0)
local _, port = server:getsockname()
local errors = {}

local serving = coroutine.detach(coroutine.create(network.serve), server, function(req)
    error("no route for " .. req.path, 0)
end, { on_error = function(err) errors[#errors + 1] = err end })

local sock <close> = network.tcp.connect("127.0.0.1", port)
sock:send("GET /missing HTTP/1.1\r\nHost: localhost\r\n\r\n")
print(vector.tostring(sock:receive("*l")))   --> HTTP/1.1 500 Internal Server Error
sock:receive("*a")
print(errors[1])                             --> no route for /missing

coroutine.close(serving)
server:close()
```

### Options

`options` is a table with any of these fields.

| Field | Value |
| --- | --- |
| `idle_timeout` | How many seconds a connection may spend without progress. It defaults to 60, and a negative value lets a connection wait without limit. |
| `max_connections` | How many connections the server keeps open at once. It defaults to half of the file descriptors that the process may open, and to 65536 at most. |
| `on_error` | A function that receives the error object of a failed handler in place of the line on standard error. |

A connection makes progress when the server reads a part of a request from it or writes a part of a response to it. A connection that stays idle for `idle_timeout` between two requests closes. One that stops in the middle of a request is answered with 408 and closes, and one that stops reading its response closes as well. The time the handler takes does not count.

While `max_connections` connections are open, further clients wait in the queue of the system, and the server accepts the next one when a connection closes. When the system has no file descriptor or no memory left for a new connection, the server waits for a connection to close, or for a moment, and accepts again.

### Limits

The request line and the headers of a request are limited to 64 KiB and 128 header lines, and a request body to 16 MiB. A chunked body gives each chunk size as hexadecimal digits alone, and the line that starts a chunk is limited to 1 KiB. The framing of a chunked body, which is its chunk lines and its trailers, is limited to 64 KiB plus 8 bytes for every byte of the body. A request over a limit is answered with 431 or 413, and a malformed request with 400. The connection closes after each of these answers.
