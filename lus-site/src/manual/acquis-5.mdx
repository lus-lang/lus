Enums are first-class values representing named constants. Every member is an interned symbol associated with one enum declaration.

## Syntax

Declare an enum with the `enum ... end` expression:

```lus
local status = enum
    pending, active, completed, failed
end
```

Values are comma-separated names, and every name in a declaration must be unique. A duplicate member is a compile-time error. The enum expression evaluates to its first member.

```lus
local color = enum red, green, blue end
assert(color == color.red)
```

## Identity and equality

Each member is created once and cached by the enum. Repeated name or numeric access returns the same object, including across garbage collection cycles.

```lus
local e = enum x, y, z end
assert(e.x == e.x)
assert(e.y == e.y)
assert(e[2] == e.y)
```

Different members from one enum have distinct identities.

```lus
local e = enum a, b, c end
assert(e.a ~= e.b)
assert(e.b ~= e.c)
```

Members from different declarations also have distinct identities, even when their names match.

```lus
local e1 = enum a, b, c end
local e2 = enum a, b, c end
assert(e1.a ~= e2.a)
assert(e1.b ~= e2.b)
```

## Indexing

Access enum values by name:

```lus
local fruit = enum apple, orange, banana end
local f = fruit.orange
assert(f == fruit.orange)
```

Access by 1-based numeric index:

```lus
local size = enum small, medium, large end
assert(size[1] == size.small)
assert(size[2] == size.medium)
assert(size[3] == size.large)
```

Any enum value can be indexed to access other values from the same enum:

```lus
local e = enum x, y, z end
assert(e.x.y == e.y)
assert(e.y.z == e.z)
assert(e[1][3] == e.z)
```

## Chained indexing

Values can be chained to navigate the enum:

```lus
local e = enum a, b, c end
assert(e.a.b.c == e.c)
assert(e.c.b.a == e.a)
```

## Ordering

Enum values can be compared by their position:

```lus
local priority = enum low, medium, high, critical end

assert(priority.low < priority.medium)
assert(priority.medium < priority.high)
assert(priority.high < priority.critical)

assert(priority.critical >= priority.high)
assert(priority.low <= priority.low)
```

Ordering is defined only for members from the same enum declaration and uses their declaration position. Comparing the order of members from different declarations raises an error.

## Numeric conversion

Use `tonumber` to get the 1-based index of an enum value:

```lus
local state = enum idle, running, paused, stopped end

assert(tonumber(state.idle) == 1)
assert(tonumber(state.running) == 2)
assert(tonumber(state.paused) == 3)
assert(tonumber(state.stopped) == 4)
```

## Type checking

The `type` function returns `"enum"` for enum values:

```lus
local e = enum val end
assert(type(e) == "enum")
assert(type(e.val) == "enum")
assert(type(e[1]) == "enum")
```

## Usage patterns

### As function arguments

```lus
local mode = enum read, write, append end

local function openFile(path, m)
    if m == mode.read then
        -- read logic
    elseif m == mode.write then
        -- write logic
    end
end

openFile("data.txt", mode.read)
```

### As table values

```lus
local status = enum pending, approved, rejected end

local requests = {
    { id = 1, status = status.approved },
    { id = 2, status = status.pending },
}

for _, req in ipairs(requests) do
    if req.status == status.approved then
        process(req)
    end
end
```

### As function returns

```lus
local result = enum success, failure, timeout end

local function fetch(url)
    -- ...
    return result.success
end

if fetch("https://example.com") == result.success then
    print("Request succeeded")
end
```

## String representation and table keys

The `type` function returns `"enum"`. `tostring` identifies the member object, and interned accesses produce the same representation. Enum values can be table keys and remain distinct from strings and numbers.

```lus
local color = enum red, green, blue end
local labels = {
    [color.red] = "stop",
    [color.green] = "go",
}

assert(labels[color.red] == "stop")
assert(color.red ~= "red")
assert(color.red ~= 1)
```

Members from separate declarations keep distinct identities at the same numeric position.

```lus
local status = enum ok, error end
local color = enum red, green end

assert(tonumber(status.ok) == tonumber(color.red))
assert(status.ok ~= color.red)
```
