The `catch` expression evaluates an expression in protected mode. A successful catch returns `true` followed by every result from the expression. A failed catch returns exactly `false` and the raw error object.

## Syntax

The `catch` keyword is followed by any expression:

```lus
local success, ... = catch <expression>
```

The error object keeps its original type and identity. Strings, numbers, tables, functions, threads, vectors, and enum values all pass through unchanged. An error raised with a `nil` payload produces the string `"<no error object>"`.

```lus
local marker = { code = 42 }
local ok, err = catch error(marker)
assert(ok == false)
assert(err == marker)
```

## Return values

A catch preserves the complete result list on success.

```lus
local function values()
    return "a", "b", "c"
end

local ok, a, b, c = catch values()
assert(ok == true)
assert(a == "a" and b == "b" and c == "c")
```

An expression that returns no values gives the catch one result, the `true` status. A failure always gives two results. Normal expression-list rules still apply, so parentheses or a non-final position truncate a catch to its first result.

When only the status matters, the remaining results can be ignored.

```lus
local ok = catch someRiskyOperation()
if not ok then
    recover()
end
```

The same form makes expected failures concise in tests.

```lus
assert(not catch type())
assert(not catch coroutine.yield())
```

## Function calls

Function calls are protected directly.

```lus
local ok, result = catch require("no-such-module")
if not ok then
    print("Module not found: " .. tostring(result))
end

local ok, data = catch load(someCode)
if ok then
    data()
end
```

## If assignment

If assignment keeps the status and value in scope for both branches.

```lus
if ok, val = catch someOperation() then
    print("Success:", val)
else
    print("Failed:", tostring(val))
end
```

## Catch statements and handlers

A catch used as a statement evaluates the expression, discards its results, and suppresses an error. The optional `catch[handler] expression` form calls `handler` only when the expression fails. The handler receives the raw error object, and its first result becomes the catch error result. An error raised by the handler propagates to the surrounding code. [Acquis 20](/manual/acquis-20) describes handlers in detail.

```lus
catch cleanupTemporaryFile()

local ok, issue = catch[function(err)
    return { cause = err, operation = "load settings" }
end] loadSettings()
```
