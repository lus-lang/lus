Compiling Lus is a straightforward process. The build produces three artifacts: the `lus` interpreter, the `lusc` bytecode compiler, and `liblus` (a static library for embedding).

You will need the following tools to compile the runtime:

- The Lus source code, which can be downloaded from its [repository](https://github.com/lus-lang/lus).
- A C compiler ([gcc](https://gcc.gnu.org/) or [clang](https://clang.llvm.org/) recommended).
- The [Meson build system](https://mesonbuild.com/).
- OpenSSL development libraries (for HTTPS support)
- c-ares development libraries (for async DNS)
- Compression libraries: zlib, zstd, brotli, and lz4 (for `vector.archive`)
- A threading library. Pthreads is included by default on most systems.
- readline (macOS) or libedit (FreeBSD/NetBSD/OpenBSD) for the REPL

### Installing Dependencies

```bash
# macOS (Homebrew)
brew install openssl c-ares zstd brotli lz4

# Ubuntu/Debian
sudo apt install libssl-dev libc-ares-dev zlib1g-dev libzstd-dev libbrotli-dev liblz4-dev

# Fedora/RHEL
sudo dnf install openssl-devel c-ares-devel zlib-devel libzstd-devel brotli-devel lz4-devel

# FreeBSD/NetBSD/OpenBSD
pkg install openssl c-ares libedit zstd brotli liblz4

# Arch Linux
sudo pacman -S openssl c-ares zlib zstd brotli lz4

# Windows (vcpkg)
vcpkg install openssl c-ares zlib zstd brotli lz4
```

## Building

```bash
git clone https://github.com/lus-lang/lus.git
cd lus/lus
meson setup build
meson compile -C build
```

The `lus` interpreter and `lusc` compiler will be placed in the `build` directory. The `lusc` compiler precompiles Lus source files to bytecode.

Compiled bytecode is tied to the producing Lus version and platform. It is a trusted build artifact. Applications that accept source from an untrusted party should use the text-only `"t"` mode of `load` or `loadfile`.

### Build types

```bash
meson setup build --buildtype=release
```

The default build already enables `-O2` and LTO. The `release` buildtype additionally disables assertions via `-DNDEBUG`.

### Verification

```bash
./build/lus -v
meson test -C build
```

Tests are organized into four suites: **h1** (language integrity), **h2** (C API), **h3** (system integration), and **h4** (benchmarks). You can run a specific suite with:

```bash
meson test -C build --suite h1
```

## Installation

```bash
sudo meson install -C build
```

This installs the `lus` and `lusc` executables, headers, static libraries, and build metadata to the system prefix (typically `/usr/local`). Alternatively, copy the binaries manually:

- On macOS and Linux, you can place them in the `/usr/local/bin` directory.
- On Windows, create a directory for Lus and add that directory to your user `PATH` through Windows Settings.

## Embedding Lus

The SDK installs `lua.h`, `luaconf.h`, `lualib.h`, `lauxlib.h`, `lworkerlib.h`, `lua.hpp`, and the matching `sqlite3.h`. Unix archives carry `liblus.a` and the separate `libsqlite3.a`. Windows archives carry `lus.lib` and `sqlite3.lib`. Keeping SQLite in its own archive preserves the public `sqlite3*` embedding surface while allowing `liblus` to remain the language library.

Static consumers also link OpenSSL, c-ares, zlib, zstd, brotli, lz4, the platform thread library, and applicable platform libraries. Use the archive's package metadata with static dependency expansion:

```bash
pkg-config --cflags --libs --static lus
```

Example compilation:

```bash
gcc -o myapp myapp.c $(pkg-config --cflags --libs --static lus)
```

On Windows, `find_package(Lus CONFIG REQUIRED)` imports `Lus::lus`, its separate `Lus::sqlite3` dependency, and the external vcpkg dependencies recorded by the archive.

See [C API error handling](/manual/guide#c-api-error-handling) in the Guide for details on using the C API.
